# 复权计算性能评估测试

## 概述

这个测试脚本对比了两种复权计算实现的性能：

1. **应用层复权**（当前实现）：在 Python 中使用 pandas 进行复权计算
2. **数据库 JOIN**（优化方案）：在 InfluxDB 中使用 SQL JOIN 直接查询复权数据

## 环境要求

- Conda 环境: `quantx`
- Python: 3.11+
- InfluxDB 3.x 连接可用
- 测试数据: 需要有 K线数据和复权因子数据

## 运行步骤

### 1. 激活 Conda 环境

```bash
conda activate quantx
```

### 2. 确认数据库连接

编辑 `backend/.env` 确认以下配置正确：

INFLUXDB_TOKEN=your_token_here

```bash

```

## 性能指标说明

### 关键指标

1. **耗时（秒）**：总执行时间
2. **吞吐量（条/秒）**：每秒处理的记录数，越高越好
3. **单条耗时（毫秒/条）**：处理一条记录的平均时间，越低越好
4. **数据量（MB）**：传输和处理的数据大小

### 性能提升计算

```
性能提升 = 应用层耗时 / 数据库JOIN耗时

- > 1.2x: 数据库JOIN明显更快，建议采用
- 0.8x - 1.2x: 性能接近，根据其他因素选择
- < 0.8x: 应用层更快，保持当前实现
```

## 预期结果

### 应用层复权（当前实现）

**优点：**
- 逻辑清晰，易于调试
- 灵活性高
- 对小数据量性能足够

**缺点：**
- 两次数据库查询（K线 + 因子）
- 需要加载所有数据到应用内存
- Python pandas 计算消耗 CPU
- 网络传输开销大

### 数据库 JOIN（优化方案）

**优点：**
- 一次查询完成
- 数据库层计算，减少网络传输
- 利用 InfluxDB 索引和并行计算
- 内存占用更小

**缺点：**
- SQL 复杂度较高
- 需要处理时间对齐逻辑
- 灵活性相对较低

## 决策建议

根据测试结果，考虑以下因素：

### 采用数据库 JOIN 如果：
- ✅ 性能提升 > 1.5x
- ✅ 数据量较大（> 10000 条记录）
- ✅ 需要实时查询复权数据
- ✅ 内存资源有限

### 保持应用层 如果：
- ✅ 性能差异 < 1.2x
- ✅ 数据量较小（< 1000 条记录）
- ✅ 需要复杂的复权逻辑
- ✅ 代码可维护性优先

### 混合方案：
- 小数据量（< 30天）：应用层复权
- 大数据量（> 30天）：数据库 JOIN
- 缓存常用结果到 Redis
