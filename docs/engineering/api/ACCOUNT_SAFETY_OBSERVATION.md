# 账户准入观测与耗时诊断

Monitor 每 30 秒通过 API 的 `/internal/monitor/account-safety` 采集脱敏准入快照，
等待预算为 5 秒。采集成功只表示完整检查结果可读取，不代表账户获准交易。
超时没有 HTTP 延迟值，不纳入成功请求的 P50/P95；事故历史与交易门禁相互独立。

## 读取边界

观测接口调用 `AccountExecutionSafetyService.checks()`，与完整 `status()` 复用
同一套 18 项实时准入检查，不加载隔离订单详情，不缓存旧的准入结论。完整状态
保留原有返回字段，并在同一数据库会话中使用本次选中的账户控制记录加载详情。

隔离详情只有发现未修复的有效候选时才读取一次权威快照，多个候选复用该次证据。
没有候选或候选均已修复时不读取历史回报。快照哈希、完整性、账户权威性、序列、
订单绑定与券商终态校验均保持不变；更新但无效的报告不会遮蔽同一快照的有效证据。

## 快照查询索引

前向迁移 `20260831_0041` 新增 `ix_agent_report_snapshot_lookup`，顺序为
`message_type`、`protocol_version`、`CAST(payload ->> 'snapshot_id' AS VARCHAR)`、
`received_at DESC`。ORM 定义与迁移保持一致。

查询固定 JSON 路径在 SQL 编译时展开，实际快照 ID 继续作为绑定参数。这样通用
预编译计划也能匹配表达式索引，不需要扫描整个历史回报表。SQLite 单元测试使用
同一表达式，并由 SQLAlchemy 编译为正确的 JSON 路径。

## 运行诊断

总耗时达到 1 秒时记录一条 `Account safety slow read` 警告，包含 `total_ms`、
`base_query_ms`、`market_ms`、`details_ms` 与 `error_type`。失败和取消同样记录
已经消耗的时间；异常只输出类型，不包含账户、快照正文、SQL 参数或凭据。

验证时应检查真实查询计划使用该索引，并从维护恢复后的时间点单独统计 Monitor
采样。30 分钟窗口的目标是零次观测超时、成功请求 P95 小于 1 秒；保留原有事故，
不得通过清空历史、放宽超时或关闭交易安全检查来满足验收。
