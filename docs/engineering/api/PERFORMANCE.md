# 多进程性能与容量指南

优化前先按组件观测 API 延迟、Engine 消费滞后、outbox/inbox backlog、
Prefect queue、Agent 心跳和数据库连接池，不用单进程总 CPU 代替链路指标。

## 优先顺序

1. 保持 API 请求路径无阻塞，不在 API 中运行策略、Prefect 或 QMT。
2. 为消息箱消费使用有界批次与幂等唯一索引；Redis 只缩短唤醒延迟。
3. Engine 只允许一个租约持有者，避免用多实例吞吐换取重复订单风险。
4. 行情大批量传输使用请求 ID、批次序号、压缩与 SHA256，不塞入
   WebSocket 控制信道。
5. 前端构建以真实 bundle 报告为依据，按路由拆包并避免重复依赖。

任何优化都不得削弱订单幂等、审计、T+1、资金或可卖量约束。
