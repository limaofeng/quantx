# QuantX Web UI/UX 设计系统

> 状态：权威规范（2026-08-24 起生效）  
> 范围：QuantX 桌面 Web Studio。原生 iOS 遵循
> [`docs/product/ios/design-system.md`](../../product/ios/design-system.md)。

## 1. 目标与优先级

QuantX 是个人 A 股量化终端。界面以深色、高密度、长时间可读和风险可辨为目标；
不把品牌或装饰色混入行情和交易事实。

颜色的决策优先级从高到低为：

1. 金融事实与交易风险语义；
2. 系统状态（成功、警告、阻断、信息）；
3. 通用交互（导航、选中、焦点、普通操作）。

因此，页面“当前选中”“可点击”“已聚焦”并不表示上涨、买入或风险，默认必须
使用蓝色交互色。只有表达第 1、2 类事实时才可使用红、绿、琥珀或危险色。

## 2. 基础视觉

- 默认形态：深色 Studio Workbench；桌面鼠标、键盘和高密度数据阅读优先。
- 表面层级：工作区/背景 `#050B16`、主面板 `#0B1728`、次级面板
  `#0F1D30`；用细边框和层级区分区域，不用大面积高饱和填充。
- 文本层级：主文字 `#F8FAFC`、次级 `#CBD5E1`、弱文字 `#94A3B8`、注释
  `#64748B`。
- 圆角和间距：工作台结构以 6–8px 圆角、紧凑工具栏、表格和面板为主；卡片仅用于
  可比较实体、局部框选和空状态。

## 3. 颜色 Token 与语义

实现值以 [`apps/web/src/index.css`](../../../apps/web/src/index.css) 为准；业务组件
优先使用语义 class、`financialToneClass` 或 Studio theme helper，而不是复制十六
进制色值。

| 角色                    | 深色默认值                | 用途                                                 | 禁止用途                 |
| ----------------------- | ------------------------- | ---------------------------------------------------- | ------------------------ |
| `brand.interaction`     | `#3B82F6`                 | 默认导航、标签、选中、普通 CTA、重试、刷新、链接强调 | 行情涨跌、买卖结果、错误 |
| `brand.hover`           | `#2563EB`                 | 普通交互的 hover/pressed                             | 风险与警告               |
| `brand.focus`           | `#3B82F6`                 | 键盘 focus ring、选中边框和状态点                    | 行情方向                 |
| `brand.interactionSoft` | `rgba(59, 130, 246, 0.14)` | 选中或轻 hover 背景                                 | 交易成交状态             |
| `market.up`             | `#EF4444`                 | A 股上涨、买入、正收益、涨停、红色 K 线              | 导航、普通选中、成功     |
| `market.buyCta`         | `#DC2626`                 | 大号买入确认 CTA（白色文字）                         | 通用 CTA、错误           |
| `market.down`           | `#22C55E`                 | A 股下跌、卖出、负收益、绿色 K 线                    | 普通成功或已完成         |
| `position.down`         | `#60A5FA`                 | 持仓语境下的下跌/亏损，降低与卖出/成功混淆           | 通用交互主色             |
| `market.flat`           | `#94A3B8`                 | 平盘、无变化、不可用数值                             | 可点击状态               |
| `state.success`         | `#10B981`                 | 非行情的完成、连接正常、可执行                       | 市场下跌                 |
| `state.warning`         | `#F59E0B`                 | 数据延迟、待确认、准备中                             | 普通强调                 |
| `state.danger`          | `#F43F5E`                 | 阻断、拒单、错误、破坏性操作                         | 普通选中和导航           |

浅色主题的金融文字 Token 分别使用 `#B91C1C`、`#15803D` 和 `#1D4ED8`；它们是同
色相的较深版本，以保证白色表面上的正文对比度。深色 Studio 则使用上表的精确产品色。

### 3.1 交易方向

- 买入使用 `market.up`；大号确认按钮使用 `market.buyCta` 和白色文字，且必须同时
  出现“买入”等明确文案；红色不能只靠按钮外观暗示业务含义。
- 卖出可以使用绿色交易方向，但同样必须显示“卖出”等文案。
- 清仓、撤单、Kill Switch 和风险拒绝属于破坏性操作，使用 `state.danger` 并保留
  显式确认；不得把普通卖出一律渲染为危险操作。
- 红涨绿跌只描述 A 股金融事实，不等同于成功/失败。市场与系统状态必须分开使用
  `market.*` 与 `state.*`。

## 4. 交互规则

### 4.1 选中、悬停和键盘焦点

- 工作区、导航、Tab、资源树、列表行、可点击卡片、筛选项和普通主按钮的默认主题
  为 `blue`。
- 选中态使用蓝色边框、轻蓝底和/或蓝色状态点；例如
  `border-blue-400/40 bg-blue-500/10`。
- hover 使用低饱和蓝色或中性表面层级；不得因 hover/selected 使用 `red`、
  `rose`、`green` 或 `amber`，除非该控件本身表达对应业务语义。
- 每个键盘可达控件必须有可见的 `focus-visible` 指示，默认使用
  `ring-blue-400/70` 或等价语义 Token；禁止只移除 outline。
- 交互反馈只改变颜色、边框、背景或阴影，不得用会造成布局跳动的 scale 动效。

### 4.2 主题实现边界

- `apps/web/src/index.css` 中的 `--studio-primary`、`--ring` 和
  `--button-primary` 是默认蓝色交互来源。
- `apps/web/src/components/studio-workbench/themeStyles.ts` 的其他主题是局部、
  显式选择的变体；新页面和通用 Studio 壳层不得把 `red` 当作默认主题。
- 新增或修改金融数值必须通过
  `apps/web/src/shared/utils/financialColors.ts` 的语义 helper 或同等集中 Token，
  不得以通用品牌色替代涨跌方向。
- 触及旧组件的红色选中、hover、focus 或普通 CTA 时，应在同一改动中迁移到蓝色；
  触及红绿行情、买卖方向、风险或状态时，不得为“统一主色”而改掉其业务语义。

## 5. 无障碍与数据表达

- 颜色不是唯一信息载体：涨跌显示正负号；买卖和风险显示文字与图标；数据状态显示
  原因和更新时间。
- 正文与背景的对比度至少满足 WCAG AA；小字号、弱文字和半透明背景在实际深色
  表面上复核，不以缩小字体规避对比度问题。
- 键盘 Tab 顺序与视觉任务顺序一致；图标按钮提供可访问名称；错误使用可读文案和
  可宣告的状态，而不只是红色边框。
- 动效应在 150–300ms 内完成，并尊重 `prefers-reduced-motion`；行情更新不得造成
  整块内容闪烁。

## 6. 实现与验收

新增或调整 Web UI 时：

1. 判断颜色是否表达业务事实；不是事实即使用蓝色交互色。
2. 优先复用全局 Token、Studio `themeStyles` 和 `financialColors`，不在业务组件
   复制一组新的色值。
3. 为新增的选中/焦点或金融语义增加针对性测试；至少断言交互蓝色与红绿金融语义
   没有互相覆盖。
4. 在桌面浏览器检查 normal、hover、selected 和键盘 focus；同时确认没有控制台
   错误或溢出。
5. 执行受影响范围的 `npm run check`、`npm run lint`、测试和生产构建；涉及
   GraphQL 契约时再按根目录规则执行 codegen。

## 7. 规范关系与变更

- 本文是 QuantX Web UI/UX 与颜色语义的唯一权威规则。
- `docs/plans/studio_visual_migration_plan.md` 的历史“Quant Red”默认决策已废止；
  该计划只保留迁移范围与架构信息，颜色规则以本文为准。
- 变更颜色语义、默认主色或 Token 前，必须在同一提交中更新本文、受影响实现、测试
  和根目录 `AGENTS.md` 的引用；不得只改页面局部样式。
