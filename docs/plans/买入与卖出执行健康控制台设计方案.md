# 买入与卖出执行健康控制台设计方案

> 状态：已批准并实现  
> 日期：2026-08-25  
> 范围：QuantX 桌面 Web Studio 的 `/entry-plans` 与 `/liquidation`

## 需求简报

### 目标

- 用户问题：买入管理只显示简略运行信息，卖出管理只有持仓导航与局部预检；用户无法在执行前快速确认账户真源、实盘能力、对账、Agent、订单链及当前标的门禁是否一致。
- 目标用户：QuantX 唯一个人账户的操作员。
- 成功标准：用户在不离开当前买入或卖出任务的情况下，能在 5 秒内回答“现在能否执行、为什么、数据是否新鲜、下一步该做什么”。

### 范围

- 包含：买入与卖出页的共享“执行健康”入口、右侧抽屉、账户级公共健康、页面专属诊断、加载/异常/阻断/健康状态、键盘与焦点行为。
- 不包含：重做做 T 健康控制台、修改交易状态机、增加多账户能力、在健康抽屉内直接修改实盘授权、原生 iOS。
- 保留行为：全局底部交易安全状态条仍展示账户级摘要并继续进入交易安全设置；买入左侧计划导航、买入计划摘要、卖出左侧持仓导航及现有清仓确认流程保持不变。

### 约束

- React 18、TypeScript、Tailwind、Lucide、Radix Sheet、URQL。
- 遵循 `docs/engineering/web/UI_UX_DESIGN_SYSTEM.md`：深色高密度、蓝色普通交互、A 股红买绿卖、系统状态使用独立语义色。
- 桌面优先：1440px 为完整停靠式体验；1024px 以下使用覆盖式 Sheet；Web 不承担原生 iOS 设计。
- 中文界面；颜色不得成为唯一信息载体；抽屉打开后聚焦标题/首个操作，关闭后焦点返回触发器。

## 设计系统

- 导航与壳层：保留现有 Studio Activity Bar、业务左侧栏与底部安全状态条；健康抽屉是右侧 utility surface，不新增一级导航。
- 布局与密度：392px 宽，12px 内边距；顶部结论、四格状态矩阵、首要阻断、链路详情、页面专属诊断、底部操作依次排列。
- 响应式：≥1440px 可与内容并排；1024–1439px 覆盖式抽屉；更窄时宽度 `min(92vw, 392px)`。
- 语义颜色：普通选中/刷新为蓝；健康为 emerald；等待/陈旧为 amber；阻断/拒绝为 rose；买入事实为红、卖出事实为绿。
- 字体：继承 QuantX 当前无衬线正文；代码、时间、版本、金额使用现有等宽字体。拒绝引入新的外部字体。
- 间距与尺寸：4/8/12/16px 节奏；状态单元最小高度 54px；主要点击目标至少 32px，关键操作至少 40px。
- 圆角、边框与阴影：6–8px 圆角、`white/5` 细边框、低透明表面；只在覆盖式抽屉使用克制阴影。
- 图标：只使用 Lucide；`ShieldCheck`、`ShieldAlert`、`RadioTower`、`TimerReset`、`DatabaseBackup`、`ArrowLeftRight`。
- 动效：150–200ms 位移与透明度；尊重 `prefers-reduced-motion`；实时更新不闪烁整块内容。
- 键盘与无障碍：Radix Sheet 管理焦点与 Escape；状态变化使用 `aria-live="polite"`；错误使用 `role="alert"`；触发器包含状态文字而非只显示颜色点。
- 反模式：不复制做 T 的 READY 信号分布；不把“安全关闭”渲染为系统故障；不在抽屉内放授权/清仓危险 CTA；不出现装饰性图表或仪表盘。
- 复用组件：`Button`、`Sheet`、`StatusBar`、`TradingSafetyProvider`、`AccountExecutionSafetyQuery`、`financialToneClass`。

## 信息架构

### 抽屉固定结构

1. **结论区**：`账户健康`、`交易权限`、账户号、检查时间、刷新按钮。
2. **四格状态**：Engine、QMT Agent、账户对账、订单回报链。
3. **首要阻断**：一条最重要原因；无阻断时显示明确通过文案。
4. **链路与真源**：快照年龄、协议版本、队列延迟、死信/告警、外部委托/成交。
5. **页面专属区**：买入计划诊断或卖出库存诊断。
6. **底部操作**：刷新、安全设置；仅在已有权威动作时显示同步/对账。

### 买入专属区

- 全局自动买入：运行 / 主动暂停。
- 当前计划：建仓/加仓、自动授权、最高可买价、今日剩余额度、剩余预算。
- 当前 blocker：使用服务端 `blockedReasons`；无阻断显示“计划条件等待中”而不是“健康”。
- 在途事实：待确认意图、工作买单；ACK 不计为真实已买。

### 卖出专属区

- 账户能力：突出 `canReduceRisk`，即使 `canIncreaseRisk=false` 也可以显示“仅减仓可执行”。
- 当前持仓：总量、可卖、冻结、在途、昨日持仓。
- T+1 诊断：今日不可卖量与可卖老仓，文案说明由风控在确认时重新裁决。
- 卖出链路：活动退出计划、工作卖单、最近真实回报；普通卖出使用绿色方向语义，清仓危险操作继续使用 danger。

## 实现与验收记录

### 已实现

- 新增共享 `ExecutionHealthControl`，由买入管理和卖出管理复用同一账户健康壳层。
- 买入诊断接入当前计划的授权、预算、最高可买价、在途委托、待确认意图和服务端 blocker。
- 卖出诊断接入所选持仓的总量、可卖、冻结、T+1、在途数量、工作卖单和退出计划。
- 查询失败时保留最近成功快照，但将整体能力降为“状态未知 / 安全关闭”，不把陈旧数据视为可执行。
- Radix Sheet 提供焦点陷阱与 Escape 关闭；关闭后焦点恢复到“执行健康”触发器。

### 与预览的差异

- 预览中的账户、计划和持仓数字均为演示数据；实现始终显示当前会话的真实查询结果。
- 宽屏使用透明遮罩的右侧 Sheet，视觉上保留并排阅读；窄屏使用暗色遮罩强调当前诊断任务。
- 首版没有新增“立即对账” mutation；“刷新状态”只重取既有查询，“打开安全设置”沿用现有安全入口。
