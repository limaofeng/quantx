# 做 T 助手 P8 模型评估冻结草案

状态：`DRAFT / 待用户确认`，2026-09-09。用户已同意先整理方案，未确认以下数值，
不授权正式训练、FINAL、SHADOW 实际运行或 ACTIVE 发布。这些数值是可审阅的建议，
不是已有实验结论，也不保证模型能够通过。

依据：[目标设计 §14](../architecture/多标的做T助手新架构设计.md)、
[实施方案 P8](多标的做T助手新架构开发实施方案.md)。工程夹具测试可继续。

## 1. 数据与共同坐标

- 候选固定为 RULE_ONLY、三分类 Logistic、三分类 LightGBM；不追加模型或主 horizon。
- 建议主 horizon 为 **300 秒**。标签从 anchor 后第一个可执行 BUY 价格开始，包含费用、
  spread、滑点和 P5 冻结的最小净 edge；target/stop 的具体值必须随 P5 口径一起确认。
  不从模型表现反推 barrier，不事后改为 60/900 秒。
- anchor 为每个合格的 COMPLETE 1 分钟 Feature Bar 的可用时点，覆盖没有候选的样本。
  特征截止、到达与推理完成时间分别保存；标签采用有序 Tick first-touch。
  缺失路径、无法成交或无法证明触达顺序记 UNAVAILABLE，不能当 NO_TOUCH。
- 建议至少 **60 个共同有效交易日**：前 40 日 DEVELOPMENT，后 20 日 FINAL；
  标的集合、实际日期、费用/滑点、P5 模拟账户和组合额度在运行前冻结。
  当前未断言已有足够数据；数据不足时等待，不用合成数据填补正式样本。
- DEVELOPMENT 每个可训练类别至少 100 个有效标签；FINAL 每类至少 30 个。
  组合比较要求 FINAL 至少 100 个规则合格候选和 20 个完整交易闭环；不足则结论为
  INSUFFICIENT，不降低门槛或追加 FINAL 天数重试。
- 同一不可变 dataset/spec、行情、账户、费用和执行链重放三种排序；模型只在规则合格集
  内排序。未成交、被容量拒绝、停牌和异常样本保留在统计与审计分母中。

## 2. 切分与实验预算

DEVELOPMENT 使用三次按交易日递增的 walk-forward：训练/评估分别为第 1–20/21–25 日、
1–25/26–30 日、1–30/31–40 日。每个训练区间末 20% 的交易日仅用于概率校准，
不得参与基础模型拟合。按完整标签区间 purge 所有跨边界样本，边界再 embargo 300 秒。
午休和跨日标签按冻结 label spec 处理，不能把墙钟间隔当作连续可交易路径。

| 候选 | 固定参数组 | 数量 |
|---|---|---:|
| RULE_ONLY | 原冻结规则分数，P5 配置不变 | 1 基线 |
| Logistic | L2，C ∈ {0.1, 1, 10}；训练集标准化，max_iter=1000 | 3 |
| LightGBM | (num_leaves,max_depth) ∈ {(7,3),(15,4),(31,5)}；100 棵树，learning_rate=0.05，min_child_samples=50，无随机子采样 | 3 |

- seed 固定为 20260909，CPU 单线程；不额外尝试 seed、特征组合或 early-stopping 轮次。
- 每组每折一次基础拟合与一次三分类 temperature 校准：最多 18 次基础拟合；
  选定唯一候选后允许一次全 DEVELOPMENT 重训（仍保留末 20% 校准集）。
  **上限为 19 次基础拟合、19 次校准拟合**；不把失败后改参数算作同一次。
- 候选先通过下方 DEVELOPMENT 门，再按日均组合净收益增量排序，平局选多分类 Brier
  更低者，再平局选 Logistic。没有候选通过就结束，不进入 FINAL。
- 锁定单一候选、配置、制品及全部分析脚本后，FINAL 只运行一次。FINAL 失败即不发布；
  不能换第二名、换样本、增加试验或重看同一 FINAL 调参。工程错误重跑必须留下错误证据，
  重新确认是否仍构成未查看结果的有效 FINAL，不能自动重试。

## 3. 建议准入门

DEVELOPMENT 门以合并的三折 OOS 结果计算；FINAL 门独立计算，全部 required 项同时通过。

| 维度 | 建议判据 |
|---|---|
| 组合收益增量 | 在相同起始净资产下，模型相对 RULE_ONLY 的日均净收益率增量 > 0；按完整交易日成块 bootstrap，2000 次、固定 seed，其 95% 区间下界 > 0 |
| 最坏分组 | 按预冻结的标的、上午/下午、训练集确定的波动率三档分组；每组至少 30 个规则合格候选。样本充分组的平均净增量均 ≥ 0；任一必需组不足，结论 INSUFFICIENT |
| 回撤与安全 | 满足 P5/P7 已确认的绝对回撤与熔断上限；最大回撤不高于同坐标 RULE_ONLY。重复单、超额度、T+1/owner 违规必须为 0 |
| 概率质量 | 多分类 Brier = mean(sum((p−onehot)²))，比仅用训练集类别频率的常数概率基线至少改善 5%；该概率基线不等同于 RULE_ONLY 交易收益基线 |
| 校准 | Top-label ECE ≤ 0.05，固定 10 个等宽概率区间；ECE 样本至少 1000，逐类同时报告，不用最高类准确率代替校准 |
| 有效覆盖 | COMPLETE anchor 中成功生成合法三分类分数的比例 ≥ 99%；失败原因逐项记录。ACTIVE 候选只接受完整 required features 和 IN_DISTRIBUTION 分数 |
| OOD | 只用基础训练集均值/总体标准差逐列标准化，距离为 sqrt(mean(z²))；零方差列的新值不等于训练常量即 BLOCK。距离高于训练集 99% 分位记 WARN，高于 99.5% 分位记 BLOCK（线性分位插值）；其余 IN_DISTRIBUTION。统计与阈值随制品冻结，不在 FINAL 重估 |
| 推理性能 | 目标 Windows CPU、单线程、单标的一分钟推理 p99 ≤ 20 ms，连续 10000 次测试；模型缺失、损坏、超时、过期均不得静默切回规则 ACTIVE 排序 |

Bootstrap 只量化当前冻结样本的不确定性，不替代交易日数量、样本独立性或未来运行观察。
波动率切点、分组与上述阈值不能在看过 FINAL 后调整。P5/P7 的绝对风险阈值尚未确认时，
此草案不能单独形成完整发布许可。

## 4. 制品与发布

- 制品记录 feature/label spec、列顺序、归一化/缺失值语义、校准与 OOD 参数、训练数据 hash、
  软件版本、model/binding/authorization revision；每个文件有 SHA-256 和大小上限。
- Engine 只接受受控的 CPU 推理格式；不加载 pickle/joblib 或制品内可执行代码。
  缺文件、hash 不符、非有限概率、和不为 1、版本漂移均 fail-closed。
- SHADOW 只记录分数与比较，不改变 RULE_ONLY 排序；建议在 P5 和稳定 PAPER 数据齐备后，
  观察至少 5 个有效交易日，再确认 ACTIVE 发布窗口。
- ACTIVE 还依赖 P7 完成、上述门通过和人工发布；必须使用新 config/successor。
  ACTIVE 模型故障阻断新 ENTRY，原有 ExitPlan 和回报继续收敛。
