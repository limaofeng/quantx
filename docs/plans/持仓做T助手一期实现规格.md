# 持仓做 T 助手一期实现规格

## 1. 目标与边界

一期实现面向账户全部持仓的“正 T”助手：通过一个全局入口启停和配置，后台自动发现该账户当前及后续新增的合格 A 股持仓，并通过 Tick 发现回撤反弹或早期快速拉升机会。买入由人工确认；买入发生真实成交后，系统持续按本批次净收益监测，并在涨停触达、动态退出、硬止损或收盘保护触发时自动提交卖单。

一期不包含：自动买入、先卖后买的反 T、同标的多批次并行、隔夜保留 T 批次，以及 QMT Agent 内运行策略。跨标的资金竞争只实现账户级并发批次数与总 T 暴露上限，不做机会评分或资金最优分配。

用户只操作一个账户级全局监控器，不需要逐只股票启动。每个账户配置只绑定一个 `StrategyRun`；该运行声明 `INSTRUMENT_SCOPE=MULTI` 和 `INSTRUMENT_UNIVERSE_MODE=ACCOUNT_HOLDINGS`，其 `instruments` 由持仓快照动态维护。策略在 `instrument_states[stock_code]` 下隔离信号、订单、成交和退出状态。固定标的策略仍遵守单实例单标的原则。实盘模式必须显式确认“自动卖出授权”；默认入口使用模拟模式。

### 1.1 全局编排规则

- 独立快捷入口为 `/t-trade`，桌面主导航显示“做T助手”，移动端显示“做T”；清仓页和个股持仓详情不再提供逐股启动入口。
- 全局设置按账户持久化，包括启用状态、运行模式、信号参数、动态退出参数、收盘保护和忽略股票代码名单。
- 后台默认每 10 秒向 miniQMT 拉取一次完整持仓快照并原子持久化，然后用该快照协调策略标的池；委托/成交引发的持仓回调即时增量落库。数据库是后端消费快照的持久化载体，miniQMT 才是实盘持仓真源。
- 完整快照记录 `source / sequence / reported_at / received_at / is_complete`。断线、异常、`None` 或不完整结果不得清空旧持仓；只有明确成功的完整空列表才表示空仓。旧序列不得覆盖新序列。
- 持仓量大于 0、属于 A 股且未在忽略名单中的股票进入动态标的池；昨日可用库存不足 100 股时保留为不可开仓状态，以便后续快照自动恢复资格。新增持仓无需用户再次启动。
- 修改全局参数时原地更新运行实例。尚未确认的旧版本信号作废；真实买入首次成交时冻结本批退出参数，已有批次继续使用冻结快照，批次归零后新信号才使用新配置。
- 停止全局监控、清仓或将股票加入忽略名单，不得直接丢弃已有批次。空闲子状态从 universe 移除；有活动批次的子状态保留并进入 `DRAINING`，只允许自动退出。
- 关联的策略运行进入 `ERROR / STOPPED / COMPLETED` 等终态时，无活动批次可安全停止并新建运行；仍有活动批次时禁止自动迁移，停止标的协调并在页面明确报错，避免丢失退出状态。
- 全局编排器不运行策略逻辑，不把内存或 Redis 当交易状态真源；策略仍通过统一 `StrategyBase.step()` 执行。

## 2. 交易语义

- 信号不是订单，人工确认也不是成交。
- 买入确认后仍须经过信号 TTL、价格偏离、资金、交易时段、停牌、涨跌停、100 股整数倍和 OrderSizer/风控检查。
- 买入与卖出数量以券商成交回报为准；部分成交按实际成交数量监控和退出。
- 当日买入股份不能直接卖出。自动卖出使用同标的昨日可卖库存完成 T+1 库存置换，置换过程必须进入 BucketLedger 和 DecisionTrace。
- 动态持仓快照中的昨日老仓在该账户级策略运行内保守初始化为“核心仓”，本批 T 买入归入“活跃仓”；退出时由风控生成 `swing -> core` 同标的库存置换计划。存在活动批次或待处理意图时不得用下一次快照覆盖运行内 bucket 状态。
- 实盘委托与成交的唯一真源是 miniQMT 回报，不以策略状态、提交成功或前端状态代替成交。

## 3. 一期信号

信号有两条互补且都只生成正 T 买入意图的路径。快速拉升不是卖出信号，也不要求先卖出再买入。

回撤反弹路径默认观察最近 300 秒 Tick，并要求：

1. 窗口高点到低点的回撤不小于 0.8%。
2. 最新价较窗口低点反弹不小于 0.2%。
3. 低点形成后至少稳定 15 秒。
4. 买一卖一价差不超过 3 个最小价位。
5. 有效盘口必须同时存在买一和卖一。
6. 若可计算当日 VWAP，最新价不得高于 VWAP。

快速拉升路径使用严格因果窗口，只读取当前 Tick 及之前的数据，默认要求：

1. 最近 60 秒从窗口低点上涨不小于 0.8%，且上涨持续至少 15 秒。
2. 最新价位于该窗口高点附近，偏离不超过 1 个最小价位。
3. 拉升阶段每秒成交额至少为此前 300 秒基线的 2 倍，且基线覆盖率不低于 80%。
4. 最新价相对当日 VWAP 溢价位于 2.0% 至 3.5% 之间：下限确认强势状态，上限拒绝末端追高。
5. 买一卖一价差同时不超过 10 个最小价位和最新价的 0.3%，且盘口完整。

当日 VWAP 必须使用累计成交额除以累计成交股数。XTData 的 `volume` 单位为手，`pvolume` 单位为股；策略只使用 `pvolume` 计算 VWAP，缺失时保守判定动量 VWAP 不可用，禁止用 `volume` 生成约 100 倍的错误 VWAP。

每次未触发都记录明确原因，例如 Tick 或基线不足、回撤不足、低点未稳定、成交加速不足、VWAP 强度不足、溢价过高、价差过大或盘口缺失。

## 4. 人工确认闸门

- 信号默认有效期 30 秒。
- 确认时以当前可执行卖一价重新检查；相对信号参考价偏离超过 0.3% 时作废。
- 确认只能消费一次，确认、忽略、过期互斥。
- 进程重启后只恢复数据库中仍为 `AWAITING_APPROVAL` 的意图，并沿用原创建时间计算剩余 TTL，禁止重建一个新的 30 秒窗口。
- 通过确认后才进入统一的 OrderSizer、OrderRiskLayer 和 Broker 路由。

## 5. 单次数量

策略只提出期望量，最终合法数量由执行层确定。默认目标单次金额为 10,000 元，单次金额硬上限为 12,000 元。信号触发时使用最新卖一价按整手计算：

```text
每手金额 = 最新卖一价 × 100
目标手数 = floor(目标单次金额 ÷ 每手金额)
目标手数不足 1 手时，若一手金额不超过硬上限，则按 1 手计算
单次策略数量 = min(目标手数 × 100, floor_100(昨日可卖库存))
```

若一手金额已经超过单次金额硬上限，则不产生买入意图。此外还要受可用资金、标的交易规则、账户总 T 暴露上限和当前未完成订单约束。确认信号时使用最新卖一价再次检查硬上限，防止价格变化绕过限制。

账户级确认闸门默认还要求：活跃批次与已确认未成交批次合计不超过 3 个，全部 T 批次估算暴露不超过账户总资产的 10%。等待人工确认的候选信号不占额度；点击确认时重新检查并预占，拒单、撤单、过期或异常时释放，部分成交时只保留尚未被成交明细接管的暴露。若委托 `FILLED` 回报早于成交明细，预占和批次数必须继续保留，直到成交明细已经写入策略批次状态。

## 6. 动态退出

监控收益使用本次 T 批次真实买入均价、实际成交数量和当前可执行买一价，按买卖双边佣金、最低佣金、过户费及卖出印花税估算净收益率。

默认参数：

| 参数 | 默认值 | 含义 |
| --- | ---: | --- |
| 止盈武装线 | 2.0% | 峰值净收益达到该值后启用动态保护 |
| 初始保护线 | 0.5% | 刚达到 2% 时允许回落到的最低净收益 |
| 初始回撤间距 | 1.5% | 2.0% 峰值与 0.5% 保护线的间距 |
| 间距增长斜率 | 0.25 | 峰值每增加 1%，允许回撤再增加 0.25% |
| 最大回撤间距 | 3.0% | 趋势延续时允许回撤的上限 |
| 高利润保护 | 开启 | 买一净收益峰值达到 4.0% 后启用更紧保护 |
| 高利润最大回吐 | 1.2% | 高利润区的保护线不低于峰值减 1.2% |
| 极速反转窗口 | 15 秒 | 只识别新峰值形成后的短时快速回落 |
| 极速反转阈值 | 0.8% | 买一净收益相对峰值回吐达到该值 |
| 极速反转确认 | 2 Tick | 连续两个 Tick 满足条件才紧急退出 |
| 涨停触达退出 | 开启 | 可执行买一达到当日涨停价时立即退出本批次 |
| 涨停容差 | 0 Tick | 默认必须由买一真实触达涨停价，不以最新价单独触发 |
| 硬止损 | -0.8% | 未武装止盈时仍始终生效 |
| 收盘保护 | 14:50 | 有未完成 T 批次时触发自动退出 |

设峰值净收益为 `P`，上一次保护线为 `F_prev`：

```text
gap(P) = clamp(1.5 + 0.25 × (P - 2.0), 1.5, 3.0)
normal_floor(P) = max(F_prev, 0.5, P - gap(P))
floor(P) = max(normal_floor(P), P - 1.2)  当 P >= 4.0%
```

保护线只升不降，峰值、当前净收益和保护线统一使用可执行买一计算。峰值为 2%、3%、4%、8% 时，默认保护线分别为 0.5%、1.25%、2.8%、6.8%。高利润峰值形成后 15 秒内，如果买一净收益连续两个 Tick 回吐至少 0.8%，`RAPID_PROFIT_REVERSAL` 以紧急优先级触发；普通高利润保护仍保证回吐达到 1.2% 时退出。涨停触达、硬止损和收盘保护不依赖止盈是否武装。涨停触达只使用可执行买一判断，避免最新价短暂打印到涨停但盘口无法卖出的误触发。

保护性退出提交交易所对应的“最优五档即时成交剩余撤销”委托。若只部分成交，真实成交量先写入批次；剩余数量在撤销回报收敛后重新回到活动退出计划，由后续 Tick 再次评估和提交。系统不得把委托已投递或部分成交伪造成整批退出完成。

## 7. 状态机

```text
OBSERVING
  -> AWAITING_APPROVAL
  -> ENTRY_SUBMITTED / ENTRY_PARTIAL
  -> MONITORING
  -> PROFIT_ARMED
  -> EXIT_TRIGGERED
  -> EXIT_SUBMITTED / EXIT_PARTIAL
  -> COOLDOWN
  -> OBSERVING
```

买入拒绝、忽略或过期且没有成交时回到 `OBSERVING`。买入部分成交后，即使剩余委托取消，也按实际成交量进入 `MONITORING`。卖出部分成交或拒绝后继续监控剩余量并允许重新触发退出。存在未退出的实际 T 数量时禁止停止账户级策略运行；对应股票进入 `DRAINING`，其他股票仍在同一个运行实例中正常工作。

## 8. 失败与降级

- 行情、盘口或时间戳缺失：不产生更激进信号。
- 确认过期或价格漂移：作废，等待下一信号，不自动追价。
- miniQMT 未连接：实盘 Broker 拒绝路由，模拟模式仍可用于观察。
- 自动卖出被风控或 Broker 拒绝：保留活动批次数量和监控状态，记录拒绝原因，不伪造成交。
- 进程重启：恢复逐标的策略状态、活动批次、原确认 TTL 和已确认未成交额度预占；以 Broker/持仓回报重新对账。
- 14:50 后：禁止新开 T 批次；已有批次优先执行收盘保护。

## 9. 界面与审计

独立的“全局做 T 助手”页面展示：唯一策略运行 ID、标的池版本、miniQMT 快照时间、账户级总开关、运行模式、统一参数、账户级并发/暴露限制、全部持仓监控范围、各股票的监控/忽略/不可用/退出中状态、待确认信号、活动 T 批次、当前净收益、峰值净收益、动态保护线和完成次数。各股票行是同一运行实例的子状态投影。用户可从持仓列表直接加入或移出忽略名单，也可手动输入股票代码维护忽略名单。

实盘模式必须单独勾选自动卖出授权。人工确认按钮旁明确显示 30 秒 TTL 和 0.3% 价格偏离限制。所有信号、确认、拒绝、少买、自动退出原因、OrderSizer 结果、风控决策、委托回报与成交回报都进入可审计记录。

### 9.1 历史回放结束与报告

账户级历史回放允许 T 批次跨日持有，不要求当天卖出。回放到达结束点后，Engine 先撤销仍在等待成交的模拟委托，再对回放期间新增且尚未闭环的 T 批次生成 `BACKTEST_END_FORCE_CLOSE` 卖出意图。期末清算仍必须经过 `TradeIntent -> OrderSizer -> A 股风控 -> BacktestBroker -> 委托/成交回报`，只允许使用同标的可卖库存进行 T+1 替代，不得直接改现金、持仓或伪造成交。停牌、跌停、行情缺失或可卖量不足时保留未平量，并在报告中标记“期末清算失败”。初始核心持仓不属于期末清算目标。

每次正常完成的回放在版本化回测目录生成 `t-trade-report.json` 和自包含的 `t-trade-report.html`，并登记到 `manifest.json`。前端刷新后直接展示同一份结构化结论、资金效率和批次明细。报告至少包含税费后增量、相对不做 T 的超额收益、最大回撤、税费、成交额、完成/胜出/强制清算/清算失败批次，以及以下资金效率指标：

- T 资金容量、平均/峰值占用资金、资金占用率与可用率。
- 累计周转次数、每交易日周转次数、平均与最长持有小时。
- 等待折损后资金利用率：逐批计算 `min(100%, 4小时 / 实际持有小时)`，再按实际买入资金加权；卖出等待越长，利用率越低。
- 单位占用资金日的税费后收益率。

样本内结论不得把未平仓批次排除后宣称可靠。存在期末清算失败时结论为不完整；完整闭环少于 10 批时只能标记样本不足；历史回放结论仍需不同区间和样本外验证。

## 10. 灰度与验收

建议按以下顺序开放：

1. 模拟观察至少 5 个交易日，记录信号数量、确认后成交率、手续费后胜率、最大不利波动和退出滑点。
2. 实盘白名单，账户级全局监控仅放行一只未忽略标的、单次 100 股，人工确认买入，自动卖出。
3. 验证至少 20 个完整闭环且没有重复下单、超可卖量、T+1 违规或状态假成交后，再提高单次比例。
4. 二期再评估多批次、信号评分、分段退出和参数自适应，不在一期直接扩展。

一期验收必须满足：

- 信号确认前零 Broker 买单。
- 过期或超价格偏离的信号无法路由。
- 动态保护线只升不降，达到 2% 不立即卖出。
- 快速拉升只产生买入候选；回落、动态保护线或可执行涨停触达才产生批次卖出。
- 特发服务 `300917.SZ` 2026-08-12 Tick 固化回放可在 13:49:57 识别早期动量、拒绝 14:02:33 的末端追高，并按同一退出计划完成批次退出。
- 自动退出数量不超过本批真实买入成交量与可置换库存。
- 部分成交、拒单、重启和收盘保护均可恢复且可审计。
- 回测/模拟/实盘使用同一个 `StrategyBase.step()`，策略代码不读取账户、数据库、网络或文件。
- 多标的回测按所有标的的全局时间顺序合并 Tick/K 线，禁止按股票逐只完整回放。
