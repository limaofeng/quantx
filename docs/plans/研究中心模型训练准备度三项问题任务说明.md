# 研究中心模型训练准备度三项问题任务说明

> 状态：待处理  
> 记录日期：2026-09-07  
> 发现入口：QuantX Web /research → 概览 → 需要处理  
> 本文用途：拆分给后续独立任务诊断和解决；本文不代表问题已经修复

## 1. 背景与当前阶段

研究中心界面重构已经完成，但当前运行环境仍处于模型训练的“前置准备 / 预检”
阶段，尚未创建 DEVELOPMENT 运行。页面显示三项准备度问题：

1. 没有认证数据集；
2. 训练能力快照缺失或已过期；
3. GPU 尚未通过资格验证。

前两项会阻止“新建训练”；第三项只阻止 GPU 后端，不应阻止已经满足数据集和
能力快照门禁的 CPU 训练。

完整模型生命周期仍为：

    前置准备
      → DEVELOPMENT
      → 开发证据审阅
      → FINAL_EVALUATION
      → 冻结测试证据审阅
      → 模型登记
      → CANDIDATE / SHADOW / ACTIVE

## 2. 问题关系与处理顺序

| ID       | 问题                     | 是否阻断 CPU DEVELOPMENT | 依赖                                       | 建议顺序           |
| -------- | ------------------------ | ------------------------ | ------------------------------------------ | ------------------ |
| READY-01 | 没有认证数据集           | 是                       | 历史数据、配置、数据库和 Research CLI      | 第一               |
| READY-02 | 训练能力快照缺失或已过期 | 是                       | Prefect 部署、Worker、数据库心跳           | 可与 READY-01 并行 |
| READY-03 | GPU 尚未通过资格验证     | 否，只阻断 GPU_REQUIRED  | READY-01、OpenCL wheel、GPU 驱动和资格证据 | READY-01 后        |
| READY-04 | 综合验收                 | —                        | READY-01 至 READY-03                       | 最后               |

READY-01 和 READY-02 完成后，应先允许 CPU DEVELOPMENT。READY-03 不得成为
CPU 训练的额外门禁，但若任务目标是消除全部三项提示，则仍需完成真实 GPU
资格验证。

## 3. READY-01：没有认证数据集

### 3.1 现象

stockSelectionDatasetVersions 没有返回状态为 CERTIFIED 的可用数据集。模型训练页
因此无法选择数据集，“新建训练”保持禁用。

当前前端门禁位置：

- apps/web/src/features/research/pages/ResearchCenterPage.tsx
- apps/web/src/features/research/pages/ResearchTrainingPage.tsx
- apps/web/src/features/research/components/training/StockSelectionTrainingWizard.tsx

数据库和认证实现位置：

- packages/infrastructure/src/quantx_infrastructure/models/stock_selection.py
- packages/infrastructure/src/quantx_infrastructure/repositories/stock_selection_training_repository.py
- apps/research/src/quantx_research/next_day_selection_dataset.py
- apps/research/configs/next_day_selection_v1.yaml

### 3.2 影响

- 无法进入新建训练向导；
- 无法创建 DEVELOPMENT；
- 无法进行依赖真实训练面板的 GPU 资格验证；
- 后续 FINAL、登记和模型阶段流转都没有输入。

### 3.3 后续任务目标

生成并持久化一个真实、不可变、可审计的次日上涨概率认证数据集，确保：

- 数据来自 QuantX 已持久化历史数据，不由训练任务直接访问 XTData/QMT；
- 数据范围、point-in-time 股票池、历史 ST、行业和退市证据真实；
- manifest、面板、质量报告的文件大小和 SHA-256 一致；
- 数据库记录和磁盘 manifest 身份一致；
- 状态只有在全部认证检查通过后才写为 CERTIFIED。

仓库已有权威命令入口：

    uv run --frozen quantx-research certify-next-day-selection-dataset --config apps/research/configs/next_day_selection_v1.yaml --dataset-version <真实且唯一的数据集版本>

数据集版本必须根据实际数据截止日和已有不可变记录确定。不得直接复用一个身份
不同的旧版本，不得手工插入 CERTIFIED 数据库行，也不得修改前端让未认证数据集
可选。

### 3.4 排查重点

1. 数据库 migration 是否已应用，stock_selection_dataset_versions 是否存在；
2. 配置的日期、股票范围、基准指数和最低上市天数是否与实际可用数据一致；
3. 日线、交易日历、指标、标签和 point-in-time 股票池覆盖是否满足认证门禁；
4. .runtime/research-datasets 下是否存在未完成、损坏或身份冲突的旧目录；
5. Research CLI 是否使用当前锁定依赖和正确 DATABASE_URL；
6. 认证失败时保留错误证据，不把部分产物登记为 CERTIFIED。

### 3.5 完成条件

- stockSelectionDatasetVersions 返回至少一个真实 CERTIFIED 数据集；
- Web “训练准备度”显示认证数据集数量大于 0；
- 新建训练向导只能列出 CERTIFIED 数据集；
- Worker 能重新校验目录、manifest、面板和质量证据；
- 重复执行相同认证请求保持幂等，身份不同的请求被拒绝；
- 相关 Research、Repository、API 和 Web 测试通过。

## 4. READY-02：训练能力快照缺失或已过期

### 4.1 现象

stockSelectionTrainingCapabilities 返回的 fresh 不是 true，或 updatedAt 缺失。
前端因此不能确认实际 CPU/GPU 能力并禁用“新建训练”。

能力快照真源不是浏览器。stock-selection-training-dispatch Prefect flow 每分钟运行
一次，在领取训练任务前执行 Research 能力探测，并将结果写入
runtime_component_heartbeats，component 固定为 stock-selection-training。

当前新鲜度门禁为 180 秒：

- apps/worker/prefect.yaml
- apps/worker/src/quantx_worker/prefector/flows/stock_selection_training_flow.py
- packages/infrastructure/src/quantx_infrastructure/repositories/stock_selection_training_repository.py
- apps/api/src/quantx_api/gqlapi/schemas/stock_selection_schema.py

### 4.2 影响

- CPU 即使实际可用，Web 也不会允许创建训练；
- GPU 状态会保守投影为不可用；
- AUTO 无法在提交前形成可信的实际后端证据；
- 放宽前端按钮或伪造时间戳会破坏训练环境的可审计性。

### 4.3 后续任务目标

恢复并证明 Prefect 部署能够持续产生新鲜、脱敏、可信的训练能力心跳。重点不是
“刷新页面”，而是修复 Worker → Research probe → PostgreSQL heartbeat → API 的
完整链路。

### 4.4 排查重点

1. quantx-pool 是否有在线 Worker；
2. stock-selection-training-dispatch deployment 是否存在、启用且保持每分钟计划；
3. 最近 flow run 是否在加载 Research CLI、连接数据库或写心跳时失败；
4. Worker 与 API 是否连接同一个 PostgreSQL 真源；
5. quantx-research probe-lightgbm-gpu --json 是否能在 Worker 环境中执行；
6. runtime_component_heartbeats 的更新时间、状态和脱敏 details 是否正确；
7. 系统时间和时区转换是否造成心跳看似来自未来或超过 180 秒；
8. full/live 交易关键时段只允许训练继续排队，但仍应更新能力心跳。

手工触发 stock-selection-training-dispatch 可能领取已经排队的训练任务。后续任务
若需要手工执行，必须先确认没有意外的 QUEUED 运行，并遵守当前测试与实盘门禁。

### 4.5 禁止的“修复”

- 增大 HEARTBEAT_MAX_AGE_SECONDS 掩盖调度或 Worker 故障；
- 在 API 或 Web 中硬编码 fresh=true；
- 只修改浏览器更新时间；
- 在 API 内直接运行训练或接管 Worker 生命周期；
- 因能力心跳失败把普通 Windows Dev 静默降级为 data-only。

### 4.6 完成条件

- deployment 连续多个计划周期成功执行；
- runtime_component_heartbeats 至少连续三次按预期更新；
- stockSelectionTrainingCapabilities 返回 cpuAvailable=true、fresh=true 和非空 updatedAt；
- 页面刷新后“训练能力快照缺失或已过期”消失；
- Worker 重启后能够在 180 秒内自动恢复新鲜心跳；
- 调度、仓储、API 投影和前端门禁相关测试通过。

## 5. READY-03：GPU 尚未通过资格验证

### 5.1 现象

训练能力返回的 gpuStatus 不是 GPU_AVAILABLE，或 qualification.gatesPassed 不是
true。该提示可能对应多种真实状态：

- GPU_UNAVAILABLE_BUILD：当前 LightGBM 没有编译 OpenCL GPU tree learner；
- GPU_UNAVAILABLE_RUNTIME：GPU 驱动、OpenCL runtime 或设备不可用；
- GPU_INSUFFICIENT_MEMORY：显存门禁不满足；
- GPU_UNQUALIFIED：缺少完整资格证据，或重复性、精度、速度、CPU reload、
  显存峰值采样等门禁未通过。

后续任务必须先读取 probe 的真实状态，不能把所有情况都当成同一种安装问题。

实现和运维入口：

- ops/windows/build-lightgbm-opencl-wheel.ps1
- apps/research/src/quantx_research/next_day_selection_gpu.py
- apps/research/src/quantx_research/cli.py
- apps/worker/src/quantx_worker/prefector/flows/stock_selection_training_flow.py

### 5.2 影响

- GPU_REQUIRED 必须失败；
- AUTO 只能保守解析为 CPU；
- CPU DEVELOPMENT 不应被这一项单独阻断；
- 在 GPU 资格证据完成前，不得显示或声称已经启用 GPU 加速。

### 5.3 后续任务目标

在当前 Windows 运行端完成真实 LightGBM 4.7.0 OpenCL wheel 构建、安装和资格验证，
生成与当前环境 requirement hash 匹配的 schema-v1 build evidence 和资格证书。

第一步只读探测：

    uv run --frozen quantx-research probe-lightgbm-gpu --json

若状态为 GPU_UNAVAILABLE_BUILD，使用仓库锁定脚本构建：

    .\ops\windows\build-lightgbm-opencl-wheel.ps1 -SourceDirectory <已核验的 LightGBM-4.7.0 源码目录> -OutputDirectory <构建输出目录>

完成 READY-01 后，使用真实认证数据集运行资格验证：

    uv run --frozen quantx-research qualify-lightgbm-gpu --dataset-dir .runtime\research-datasets\<已认证数据集版本> --build-evidence <构建输出目录>\lightgbm-opencl-build-evidence.json

不得虚构 LightGBM 源码目录、OpenCL 设备、构建证据或资格指标。安装新 wheel 属于
运行环境变更，后续任务应记录安装目标、版本、wheel SHA-256、回滚方式和验证结果。

### 5.4 资格门禁

资格成功至少需要：

- LightGBM 4.7.0 且 USE_GPU=ON；
- build evidence 的 wheel SHA-256 和当前安装一致；
- OpenCL runtime 能发现并实际使用目标 GPU；
- 真实训练重复性通过；
- CPU reload 通过；
- 训练期间显存峰值可采样；
- FP32/FP64、概率质量和排名差异在门禁内；
- 加速比和最小样本阈值满足当前资格版本；
- qualification evidence SHA-256 与 environment requirement hash 有效。

### 5.5 完成条件

- probe 返回 GPU_AVAILABLE；
- qualification.status 为 GPU_AVAILABLE；
- qualification.gatesPassed=true；
- qualification.evidenceSha256 是有效的 64 位小写十六进制哈希；
- 新鲜 Worker 心跳投影相同资格证据；
- Web “GPU 尚未通过资格验证”提示消失；
- AUTO 只在服务端资源预检满足时解析为 LIGHTGBM_OPENCL_GPU；
- GPU_REQUIRED 在资格存在时可通过，在证据删除或环境变化后继续 fail closed；
- GPU、Worker 和训练预检相关测试通过。

## 6. READY-04：综合验收任务

三个问题分别完成后，必须单独执行一次综合验收，避免“命令成功但 Web 仍不可用”。

### 6.1 验收顺序

1. 使用统一 Windows 入口确认服务处于预期的 full/live 状态；
2. 确认 Prefect Worker 和 stock-selection-training-dispatch 正常；
3. 查询 stockSelectionDatasetVersions，确认至少一个 CERTIFIED；
4. 查询 stockSelectionTrainingCapabilities，确认 CPU 和心跳新鲜；
5. 若本批要求 GPU，确认 GPU_AVAILABLE 和完整资格证据；
6. 打开 /research 和 /research/training，确认对应提示消失；
7. 打开 /research/training/new，完成预检但不提交训练；
8. 确认 AUTO 解析结果、数据集身份、manifest SHA-256 和资源估算真实；
9. 检查浏览器控制台和网络错误。

综合验收默认不创建 DEVELOPMENT、不触发真实交易，也不运行 E2E/真实交易测试。
若后续任务需要实际提交训练，必须把它作为单独明确授权的验收步骤。

### 6.2 最终完成定义

| 检查项     | 预期                                                                      |
| ---------- | ------------------------------------------------------------------------- |
| 认证数据集 | 至少一个真实 CERTIFIED 数据集                                             |
| CPU        | cpuAvailable=true                                                         |
| 能力心跳   | fresh=true，updatedAt 在 180 秒内                                         |
| GPU        | GPU_AVAILABLE 且资格门禁全通过；若任务明确接受 CPU-only，则保留解释性提示 |
| 新建训练   | READY-01 和 READY-02 完成后可进入                                         |
| 预检       | blockers 为空或只显示真实、可解释的业务阻断                               |
| 安全边界   | 无训练提交、无模型自动登记、无策略或交易副作用                            |

## 7. 独立任务拆分建议

### 任务 A：认证首个训练数据集

范围只包括 Research 数据生成、证据认证、数据库登记和查询验收。不要同时修改
Prefect 调度或 GPU 构建。

### 任务 B：恢复训练能力心跳

范围只包括 Prefect deployment、Worker probe、心跳持久化和 API/Web 新鲜度验收。
不要通过延长时限或前端放行规避。

### 任务 C：完成 Windows LightGBM OpenCL GPU 资格验证

依赖任务 A 的认证数据集。范围包括真实构建、安装、资格证据、Worker 投影和
AUTO/GPU_REQUIRED 行为验证。

### 任务 D：综合只读验收

在 A、B、C 合并后执行。只读检查 Web、GraphQL、Prefect 和运行状态；默认不提交
训练、不登记模型、不触发交易。
