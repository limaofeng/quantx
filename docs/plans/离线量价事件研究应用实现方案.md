# QuantX 离线量价事件研究应用实现方案

## 1. 目标与边界

新增独立工作区应用 `apps/research`，项目名为 `quantx-research`。它只读
PostgreSQL 和 InfluxDB，不接入 API、Engine、Worker、Prefect 或 QMT，
也不写业务数据库。常规服务禁止反向依赖 `quantx_research`。

首个研究主题是“异常放量与事前价格位置对后续走势的影响”，同时建设可复用
事件研究框架。运行链路为：

```text
只读历史数据
  -> 数据覆盖与时点检查
  -> 构造历史面板
  -> 识别事件和条件分组
  -> 计算后续走势与超额收益
  -> 事件统计、交互回归、稳健性检查
  -> 结构化结果和中文 HTML 报告
```

运行产物写入 `.runtime/research-runs/`，默认不提交。经人工评审后的研究结论
可提炼到 `docs/research/`，但研究应用不会自动发布结论或生成交易信号。

## 2. 应用组织与入口

应用内部按 `data`、`core`、`studies` 和 `reporting` 分层：

- `data` 只负责只读行情、证券、复权因子和指数数据，按代码分批读取并可缓存
  为 Parquet。长区间读取还按 180 个自然日分窗，避免 InfluxDB 3 Core
  单查询文件扫描上限。
- `core` 负责配置、运行清单、质量检查、事件去重、未来收益、Bootstrap、
  FDR 校正和回归。
- `studies` 通过统一研究协议提供具体事件定义，首个插件为
  `volume-shock/v1`。
- `reporting` 从结构化结果生成 CSV、SVG 和自包含 HTML，不重新计算指标。

CLI 提供三个命令：

```powershell
quantx-research validate --config apps/research/configs/volume_shock_v1.yaml
quantx-research run --config apps/research/configs/volume_shock_v1.yaml
quantx-research render --run-dir <run-directory>
```

2026-07-30 全市场正式研究使用
`apps/research/configs/volume_shock_v1_20260730.yaml`。该配置把分析窗口冻结为
`2021-07-30..2026-07-30`，对应数据/复权证明窗口
`2020-03-13..2026-07-30`，避免 `latest` 或最后一个已完成交易日改变研究
边界。

`validate` 只检查配置和数据覆盖；`run` 执行完整研究；`render` 只根据已有
产物重建报告。数据不足时生成 `failed_preflight` 清单并返回非零退出码，
不得生成貌似成功的报告。

默认配置省略 `universe.stock_codes`，表示 QuantX 当前证券主表中代码符合
`^\d{6}\.(SH|SZ)$`、且上市/到期区间与分析窗口相交的全沪深 A 股（暂不含
北交所）；显式填写代码列表时使用固定研究样本。证券主表属于
当前时点快照；在历史成分、历史 ST 与退市状态未完整补齐前，该总体不是严格
无生存者偏差的历史全市场样本，正式报告必须披露这一限制。
`volume_shock_smoke.yaml` 提供 2 只历史覆盖完整股票的固定短区间真实数据
冒烟运行，便于先确认数据源和报告链路，再启动耗时的全量研究。

复权因子是稀疏数据，不能用“每只股票至少有一条因子”判断完整性。正式
`validate` / `run` 必须在全量日线扫描前，从 PostgreSQL 持久化的
`market_data_request` 证明每个目标股票及沪深 300 基准均被已完成的
`qmt-get-divid-factors-v1` 请求完整覆盖研究数据窗口，且请求分片完整。
零公司行为代码由请求的 `stock_list × window` 证明为已权威同步；缺少该
证明时直接 `failed_preflight`。

正式全量链路采用可审计的磁盘 staging。股票代码被分成互斥 batch，每个
batch 包含其中每只股票的完整历史，依次完成标准化、时点可得复权、质量
检查和特征计算。随后以全部股票日期和基准日期的全局并集计算 forward
outcome。全市场等权基准必须在事件资格过滤前，对各 batch 的
`(event_date, horizon, return_kind)` 累计 `sum/count`，第二遍再回填
market excess；不得改成只对最终分析样本求均值。

最终阈值前样本按股票 batch 保存在临时 Parquet 中，配置冷却与 5/20 日
敏感性冷却都在完整单股历史上计算。PyArrow streaming writer 将分区合并成
既有单文件输出；正式文件先写同目录 partial，关闭并核对行数后原子替换。
统计阶段按用途读取窄投影：71 列全样本仅流式写产物，不整体进入 pandas；
正常量比较逐 horizon 读取。回归按不超过 65,536 行的 Parquet 块多遍累计
全样本中心、日期固定效应 normal equations 和双向聚类 score，内存复杂度
不再随全样本行数增长，也不构造全量股票/日期字符串标签。

运行期持续采样进程 RSS 和可用物理内存，不读取 pagefile 容量。正式配置
保留 8 GiB 物理内存并每 0.25 秒采样；后台锁存第一次 reserve breach，主
线程在每个有界块前后检查。预计增量加保留量不足，或已观察到 breach 时明确
`failed_resource`。这是有界块级 fail-closed 保护，不宣称为 OS 级进程内存
上限。内存遥测和 staging 规模估算进入 `data-quality.json` 与 manifest；
资源失败保留已有质量证据、数据指纹及真实已知计数，临时 staging 在命令
退出时清理。

## 3. 异常放量研究口径

主因子为：

```text
RVOL20(T) = Volume(T) / Mean(Volume[T-20:T-1])
```

基准窗口严格排除事件日。`RVOL20 >= 1.5` 定义为异常放量，分组为
`<1`、`1-1.5`、`1.5-2`、`2-3` 和 `>=3`。稳健性指标包括成交额相对
前 20 日均值及 `log(volume)` 相对前 60 日的 z-score。

事前价格位置严格使用 T-1 时点：

```text
Position252(T-1) =
  (Close[T-1] - Min(Low[T-252:T-1]))
  / (Max(High[T-252:T-1]) - Min(Low[T-252:T-1]))
```

价格位置分为低位 `0-30%`、中位 `30-70%`、高位 `70-100%`。事件日
按复权收盘收益分为放量下跌 `<-1%`、放量滞涨 `[-1%, 1%]` 和放量上涨
`>1%`。另识别放量突破和高位放量滞涨。

事件日前至少需要 252 根有效日线；上市不足 120 个交易日、事件日停牌、
价格或成交量非正的样本排除。同一股票事件设置 10 个交易日冷却期，只保留
事件簇的首次事件。当前行业成分和 ST 状态没有历史有效期，主分析不得用当前
状态反推历史。

运行前置门槛同时检查可用股票数、完整历史覆盖比例、研究截止日覆盖比例和
基准收益覆盖比例。默认全量配置要求至少 100 只股票、80% 股票历史覆盖、
90% 截止日覆盖和 90% 沪深 300 收益覆盖；不满足时必须输出
`failed_preflight`，不得把残缺股票池报告为成功。

后续走势同时输出 T 日收盘至 T+1/3/5/10/20 收盘的价格响应，以及 T+1
开盘至相应期限收盘的可观察收益；并计算绝对收益、沪深 300 超额收益与同日
全市场等权超额收益。缺失 bar 不得前向填充。

## 4. 统计与报告

报告包含 RVOL、价格位置和事件方向的条件统计与热力图；按事件日期进行
1,000 次分块 Bootstrap，随机种子固定为 42，输出 95% 置信区间。多期限
检验使用 Benjamini-Hochberg FDR 校正，单元样本少于 30 时不展示显著性
结论。

这里的 Bootstrap 分块单元是“同一事件日期的全部截面事件”，用于保留同日
股票间相关性。v1 尚未使用跨事件日期的移动区块；T+20 等重叠长周期收益仍
可能有序列相关，报告必须提示置信区间需谨慎解释。

交互回归以 `log(RVOL20)`、事前价格位置及二者交互项为核心，控制事件日
收益、前 20 日动量、前 20 日波动率、平均成交额和日期固定效应，标准误按
股票和事件日期双向聚类。由于缺少时点化行业成分，v1 不使用行业固定效应。

每次运行至少生成：

```text
manifest.json
resolved-config.yaml
data-quality.json
events.parquet
metrics.json
tables/*.csv
figures/*.svg
report.html
```

`events.parquet` 和 `metrics.json` 是事实来源，HTML 仅负责展示。manifest
记录配置哈希、研究源码指纹、`uv.lock` 校验值、Git commit、dirty 状态、
数据指纹、直接依赖版本和产物校验值。

## 5. 验收要求

- 合成行情证明 RVOL 不包含 T 日、价格位置只使用 T-1 及更早数据。
- 覆盖分组边界、冷却期、上市天数、停牌、缺失数据和公司行为。
- 未来收益按市场交易日对齐，缺失 bar 不前向填充。
- Bootstrap 固定种子可复现，FDR 和交互回归在已知合成样本上正确。
- 端到端测试生成 manifest、Parquet、CSV、SVG 和 HTML。
- 边界测试证明 API、Engine、Worker 和 QMT Agent 不导入研究包。
- 相同代码、配置和数据产生相同数据指纹与统计结果。
- `batch_size=1` 的多批 synthetic 必须与旧全内存实现逐列、数据指纹和统计
  结果等价，并覆盖全市场等权收益、全局交易日顺序及 5/10/20 日冷却。
- 混合 `int64/float64/nullable` 查询批次以及不同 batch size 必须产生完全
  相同的 canonical 数据指纹。
- 流式回归必须与旧全内存实现高精度等价，并证明不加载全样本回归投影。
- 物理内存 guard 使用注入的低内存快照时，必须锁存 breach 并在下一有界块
  前失败；错误和审计字段不得把 swap/pagefile 计为可用内存。
- 第二个输出块前注入资源失败时，正式 Parquet 不得存在，partial 必须清理；
  失败 manifest 必须保留已知样本数、事件数、数据指纹和质量证据。

离线研究核心阶段不新增数据库表、不接入 Prefect，也不把研究结论直接转换为
生产选股或交易信号。研究运行与常规服务的依赖方向保持不变。

## 6. 现有 Web 查阅层

研究计算完成后，结果在现有 QuantX Web 的“研究中心”统一展示：

```text
离线研究运行
  -> .runtime/research-runs/ 不可变产物
  -> API 只读白名单投影
  -> GraphQL 鉴权查询
  -> /research 运行索引
  -> /research/:studyId/:version/runs/:runId 独立结果页
```

Web 查阅层不执行研究、不写研究目录，也不让 API、Engine 或 Worker 导入
`quantx_research`。API 只读取最终状态的 manifest，并把数据质量、事件曲线、
量能与价格位置交互统计、回归和稳健性结果裁剪为展示 DTO。浏览器不能指定
文件路径，运行详情使用服务端生成的稳定不透明标识；HTML、YAML、Parquet、
CSV、本机路径和 Git 元数据均不通过 Web 暴露。

页面采用“统一研究中心 + 每次运行独立 URL + 可复用结果组件”的组织方式：

- `/research` 展示运行状态、研究版本、完成时间、事件数和产物质量。
- 独立结果页展示样本与数据覆盖、事件后收益曲线、RVOL × 价格位置热力表、
  交互回归、稳健性检验和解释边界。
- smoke 或事件数不足 100 的运行必须显示小样本警告，不得包装成有效因子
  结论。
- 缺失、损坏或版本不兼容的单个产物以稳定空状态或告警降级，不影响其他
  运行的索引和查阅。
- 所有 GraphQL 请求沿用现有登录态和 `market:read` 权限；Caddy 仍是唯一
  公开入口，不为 `.runtime/research-runs` 增加静态文件服务。

离线 `report.html` 继续作为可归档快照；现有 Web 直接渲染结构化数据，不以
iframe 嵌入报告。后续新增研究主题应优先复用上述页面骨架与图表组件，仅在
确有专属分析语义时增加主题面板。
