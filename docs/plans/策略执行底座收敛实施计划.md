# 策略执行底座收敛实施计划

目标：落实 2026-08-31 架构审查的八类缺陷，保留
`StrategyBase.step → TradeIntent → OrderSizer / Risk → Broker → Inbox` 主线。
本计划不是新框架或兼容层；个人单账户中的所有交易来源应遵守同一套执行约束。

## 验收清单

- [x] 账户快照与本地未结占用分离。刷新快照不能释放未结预留；LIVE 所有来源在账户锁内核验共享资金、卖出库存和保护义务，再原子创建 pending/outbox。
- [x] 正向做 T 的买入量不超过可用于退出的老仓容量。定量、审批后执行和最终入队均不能越过容量；已有卖单与其他未结 T 批次不得重复占用老仓。
- [x] PAPER 保护计划、资金和持仓不参与 LIVE 容量或授权计算；同一账户下的不同 PAPER 运行也不相互认领模拟库存。授权预览、确认与执行使用一致规则。
- [x] 托管买入计划的订单与成交按 owner、run、intent 和阶段归属推进。退出 SELL、旧入场回报不能清空当前 BUY pending。
- [x] 计划修改保留旧有效运行绑定，只有新版本就绪后切换。失败可恢复；有无内存 runtime 均依据持久化交易义务判断能否停止。
- [x] 指标窗口按周期隔离；K 线标签与可用时间明确区分；所有回测按统一因果顺序消费行情和成交，必需事件失败不能交付成功结果。
- [x] 策略决策记忆可持久化或有明确的重建和禁交易门禁。超市、动态天平和网格覆盖连续运行与 JSON 检查点恢复后的决策等价回归。
- [x] 所有交易意图采用同一个严格持久化受理边界。写入失败不得暴露可审批意图或继续路由；公共层不保留普通/专用策略两种安全标准。
- [x] 按职责收敛公共执行代码，并同步交易/Engine 契约和针对性回归测试。
- [x] 最终检查跨功能组合、边界测试、代码差异与工作区归属，按实际功能提交；不执行真实交易测试。

## 必须覆盖的组合场景

1. 1 万元现金预留 6 千元后重复接收同一券商快照，另一笔 6 千元订单不能取得执行资格。
2. 做 T 与买入计划、普通策略共用账户；未投递和已投递未终结订单均计入占用，重复命令不重复预留。
3. 100 股可用老仓、10 元股价、1 万元 T 目标，最终买入不得超过 100 股；缺少老仓事实时阻断。
4. LIVE 已保护 1000 股时增加 PAPER 100 股保护，不改变 LIVE 容量与授权。
5. 当前 BUY pending 收到旧 SELL 或旧 BUY 的终态回报，当前 pending 不变。
6. 有活跃退出保护时修改入场配置失败，旧计划仍可查询、控制和恢复；未恢复 runtime 不能绕过停止门禁。
7. 同时输入 1m/1d，分钟线不推进日线指标；日线只在实际收盘可用后进入回测，Tick 与 BAR 不倒退时间。
8. 超市、动态天平和网格策略连续运行与恢复后决策等价；交易意图持久化故障统一阻断。

## 实施记录

- 2026-08-31：复核历史审查的八类缺陷，按共享执行规则逐项修正。原有 API、卖出历史删除和回放 UI 工作保留，不纳入本任务提交。

| 问题 | 实际落点与行为 |
| --- | --- |
| 多来源争用账户容量 | `AccountCapacityService` 在统一锁内读取已处理的完整账户快照，扣除快照未覆盖的命令、卖出保护和 T 退出义务。`RuntimeStateManager` 刷新快照时保留本地未被观察到的预留；不能用较晚终态扩大旧快照容量。 |
| 正向做 T 超过老仓 | `OrderSizer`、审批后执行和最终命令入队都检查可用于退出的老仓；缺少可卖量时阻断。领先于实际成交回报的委托终态、ERROR 保护及孤立 T 批次不能让义务消失。 |
| PAPER 污染 LIVE | 模拟策略资产归属运行；独立模拟退出/清仓计划仅在创建时冻结持仓样本，之后不随真实仓位补充。授权预览、确认、保护容量和挂单检查都排除不属于当前环境的占用。 |
| 回报误推进当前阶段 | 托管 ENTRY 校验完整归属和 BUY 方向；旧入场成交只补记累计事实，退出或旧委托终态不解除当前 pending。恢复时的零成交证明采用相同归属契约。 |
| 改版或停止破坏保护义务 | 新版本就绪后原子切换有效运行绑定；失败保留旧绑定。停止门禁查询持久化意图、挂单、持仓和退出义务，未恢复 runtime 不能绕过。 |
| 多周期回放前视或时间倒退 | 统一 `BarTiming` 和回测时间线；保留原始 K 线标签，以完整可用时间排序。同时间先 Tick 后 BAR，分钟线不推进日线指标；成交消费、检查点或日结失败使回测失败。 |
| 重启/回滚丢失决策记忆 | 超市保存跟踪持仓、候选、价格历史及风险计数；动态天平保存日线窗口和确认状态；网格保存指标递推状态、触网最低价、库存和部分成交。`restore_algorithm_state()` 同时用于启动与回报回滚后的私有缓存重建。 |
| 意图持久化只做尽力写入 | 公共受理边界先完成整批严格持久化，再暴露审批或路由。写入失败不继续执行；缺失意图不能由状态更新临时补造。 |

### 验证范围和边界

最终组合回归覆盖 Engine 单元测试、交易域、基础设施、Application、Contracts、API
单元测试，以及 QMT Agent/Worker 依赖边界和 pytest 数据库隔离。
测试显式关闭真实交易，排除 `dangerous`、`real_trading`、`e2e` 标记；临时文件和
JUnit 报告写入未提交的 `.codex_screenshots/`。

最终结果：**3096 passed、2 skipped、0 failed、0 errors**，耗时 128.57 秒。
2 项跳过均为研究产物目录的符号链接测试，原因是当前 Windows 环境不允许创建测试
符号链接。17 条告警涉及依赖弃用及测试连接取消协程清理，不隐瞒为无告警运行。
各实现批次的定向 Ruff 检查与最终 `git diff --check` 通过。

最终组合命令（在仓库根目录运行）：

```powershell
$env:ENV='testing'
$env:ENABLE_REAL_TRADING='false'
$env:QMT_REAL_TRADING_ENABLED='false'
$env:PYTHONIOENCODING='utf-8'
$regressionDirectory=Join-Path '.codex_screenshots' ('strategy-foundation-' + [guid]::NewGuid().ToString('N'))
.\.venv\Scripts\python.exe -m pytest `
  tests/engine/unit tests/domain tests/infrastructure tests/application `
  tests/contracts tests/api/unit `
  tests/qmt_agent/test_dependency_boundary.py `
  tests/worker/test_qmt_boundary.py tests/test_pytest_database_isolation.py `
  --import-mode=importlib --basetemp $regressionDirectory -p no:cacheprovider `
  -m 'not dangerous and not real_trading and not e2e' -o addopts='' `
  --junitxml .codex_screenshots/strategy-foundation-final.xml -q --tb=short
```

没有重启服务、启动 QMT Agent、提交真实订单或执行真实交易/E2E 验收。本轮未改变
GraphQL schema 或前端查询，因此没有触发 codegen；工作区已有的 GraphQL/UI 改动
属于其他任务。

缺失或损坏的策略决策检查点会阻断新交易或恢复，不添加猜测历史的兼容路径。
上述自动化回归不能替代实盘市场与券商环境验收。
