# QuantX 个人 A 股量化 iOS 产品需求规格

> 版本：v1.0
>
> 状态：已批准，作为开发与验收基线
>
> 关联矩阵：[需求追踪矩阵](traceability.md)

## 1. 产品定义

QuantX iOS 是面向单个个人投资者的 **A 股量化移动控制中心**。它让用户在
iPhone 上完成当日决策、行情判断、基础交易、量化策略控制、做 T、打板、卖出
管理、风险响应和复盘；重型策略研发、回测实验和系统运维继续留在桌面端。

目标用户是通过 TestFlight 安装、经 VPN 或受控私网访问 QuantX、且只有一个
主交易账户的产品所有者。v1 不面向公开 App Store、多租户理财服务、代客操作
或多人协作。

### 1.1 产品目标

- `IOS-PLT-001`：在不使用桌面端的情况下，用户能完成交易日内最重要的查看、
  确认、控制和风险处置任务。
- `IOS-PLT-002`：使用 Swift 6、SwiftUI、Apollo iOS 和 iOS 17+ 构建原生体验，
  通过个人 TestFlight 分发，仅经 HTTPS/WSS 的 VPN/私网入口访问。
- `IOS-PLT-003`：产品只绑定当前会话解析出的唯一主账户；界面不得提供跨账户
  切换，也不得混合展示不同账户数据。
- `IOS-PLT-004`：客户端是操作与呈现端，不是交易决策真源；所有 A 股合法性、
  数量、可卖量、T+1、资金和最终订单状态由服务端统一交易链路负责。

### 1.2 成功标准

v1 同时满足以下条件才算完成：

1. 用户可以从五个主入口完成本文所有 P0 流程，不存在占位页、模拟账户事实或
   只能回桌面继续的断裂流程。
2. 所有新增实盘风险都经过服务端实时预览、设备绑定短时挑战和逐次生物确认；
   撤单只取消风险，不要求逐笔生物确认。
3. 行情、订单、成交、策略、做 T、打板、清仓和通知使用同一主账户，断线重连
   后通过查询快照恢复，不以订阅或本地缓存覆盖服务端事实。
4. 通过[发布门禁](acceptance-gates.md)，完成五个连续交易日 TestFlight 观察
   和受控实盘灰度，且无重复订单、假成交、越权或敏感信息泄漏。

## 2. 产品原则

- **行动优先**：今日页先呈现待处理事项和风险，再呈现状态摘要。
- **事实分层**：信号、预览、已确认、已排队、Agent 已收、券商已报、部分成交、
  全部成交必须使用不同状态与文案。
- **默认保守**：未知、过期、乱序、跨账户或数据不完整时禁止扩大风险。
- **专业但可理解**：保留量化解释与审计入口，主界面把内部术语翻译为结果、
  原因、风险和下一步。
- **移动端聚焦**：支持高频查看与短流程操作，不复制桌面研究工作台。
- **原生可访问**：深浅色、Dynamic Type、VoiceOver、Reduce Motion 和不依赖
  颜色的金融语义是发布条件，不是后续增强。

## 3. 信息架构需求

- `IOS-NAV-001`：底部固定为“今日、行情、交易、量化、资产”五个入口，标签、
  图标和顺序不可按后台模块任意变化。
- `IOS-NAV-002`：设置、设备会话、通知偏好、隐私和版本从资产页右上角账户入口
  进入，不占用主 Tab。
- `IOS-NAV-003`：每个业务对象拥有稳定的类型安全路由；通知深链必须先本地解锁
  和重新取数，再进入目标对象。

详细页面地图和流程见[信息架构与交互规范](information-architecture.md)。

## 4. 今日

- `IOS-TDY-001`：展示总资产、当日盈亏、可用资金、持仓市值、数据时间和账户
  风险状态；数字均来自同一账户快照。
- `IOS-TDY-002`：以优先级队列展示待确认信号、待确认退出、拒单、异常、未完成
  委托和需要人工恢复的事项；已失效事项不可继续触发原操作。
- `IOS-TDY-003`：展示策略、做 T、打板、Agent、行情和对账的摘要，明确区分
  “运行正常”“准备中”“自动交易未授权”和“阻断”。

## 5. 行情

- `IOS-MKT-001`：支持证券搜索、自选新增/删除/排序，以及自选和持仓行情列表；
  自选变更是受权限控制的持久化操作。
- `IOS-MKT-002`：股票详情展示最新价、涨跌额/幅、开高低收、成交量额、涨跌停、
  停牌和数据时间。
- `IOS-MKT-003`：提供可切换周期的分时与 K 线；图表不得使用未来数据，断档和
  陈旧区间必须可见。
- `IOS-MKT-004`：展示服务端提供的五档盘口和逐笔成交；缺档、延迟、停牌或集合
  竞价状态不得用零值伪装。
- `IOS-MKT-005`：从股票详情可进入下单票据、持仓、相关策略、做 T 或打板上下文，
  但不自动带入最终数量或提交交易。

## 6. 交易与卖出管理

- `IOS-TRD-001`：支持主账户 A 股手动买入和卖出，票据必须显示证券、方向、报价
  类型、价格、数量、估算金额、费用、可用资金/可卖量和数据时间。
- `IOS-TRD-002`：v1 只允许 `LIMIT` 与服务端明确声明可用的 `BEST`（用户文案
  “对手方最优价”）。`BEST` 仅在沪深映射 QMT `MARKET_PEER_PRICE_FIRST`，北交所
  fail-closed；服务端未返回能力时入口完全隐藏，不回退到通用 `MARKET`。
- `IOS-TRD-003`：每次实盘手动下单均执行“服务端预览 → 用户核对 → Face ID /
  Touch ID → 确认 → 服务端重新校验”；确认失败或挑战过期必须重新预览。
- `IOS-TRD-004`：订单详情持续展示排队、Agent 投递、券商受理、部分成交、成交、
  撤单、拒单和未知状态；Mutation 成功或 `command_ack` 不得显示为已报/成交。
- `IOS-TRD-005`：活动委托支持撤单。撤单提交后显示“撤单请求已提交”，直到券商
  回报才显示“已撤”；重复点击使用同一幂等键且不产生第二条撤单命令。
- `IOS-TRD-006`：支持按单只或选中持仓创建清仓计划，必须明确选择仅处理当前
  可卖量或持续处理确认快照，并显示计划冲突、T+1 和不可卖部分。
- `IOS-TRD-007`：全仓清仓只放在卖出管理二级高风险入口；预览必须列出纳入、
  跳过和冲突的持仓，确认只覆盖预览时快照，之后新增持仓不自动加入。
- `IOS-TRD-008`：支持目标价、收益率及服务端能力声明的动态规则创建条件退出计划；
  实盘自动退出必须以生物确认授权精确的账户、标的、保护量、规则、配置版本和
  授权期限，未授权计划降级为人工确认。
- `IOS-TRD-009`：风控拒绝、限量、T+1、停牌、涨跌停、资金不足、行情过期、
  Kill Switch 和对账异常都显示可理解原因及可行下一步，并保留审计编号。
- `IOS-TRD-010`：交易页提供今日/历史委托、成交和卖出计划；筛选不改变状态真源，
  所有部分成交同时显示委托量、成交量和剩余量。

## 7. 量化控制中心

### 7.1 策略

- `IOS-QNT-001`：展示策略实例、标的、模式、生命周期、最近决策、收益/风险摘要、
  数据质量、退出计划和审计入口。
- `IOS-QNT-002`：支持服务端允许的启动、暂停、恢复、停止和进入 DRAINING；有
  活跃退出计划时不得把“停止入场”表示为退出保护已停止。
- `IOS-QNT-003`：只允许修改服务端标记为 `mobileEditable` 的安全参数；字段必须
  携带类型、单位、范围、敏感级别和版本，更新使用 `expectedVersion`，版本冲突
  后刷新而不是覆盖。
- `IOS-QNT-004`：策略从模拟切入实盘或在实盘启动前必须展示账户和 readiness
  预览，并逐次生物确认；缺失任一门禁时不能提供可点击的绕过入口。

### 7.2 做 T

- `IOS-TTR-001`：提供账户级总开关、模拟/实盘模式、安全参数、监控范围、忽略
  列表、持仓资格和 readiness；客户端不自行决定持仓是否可做 T。
- `IOS-TTR-002`：待确认买入展示信号理由、价格、目标量、过期时间、退出模板和
  风险警告；批准继续使用服务端短时预览和逐次生物确认。
- `IOS-TTR-003`：展示批次、入场/退出委托与成交、净收益、保护线、DRAINING、
  自动退出和 Kill Switch；有活动批次时停止操作必须遵守服务端状态机。

### 7.3 打板

- `IOS-LUB-001`：展示候选、首次触板/封板/炸板/回封阶段、门禁、预算和当日人工
  布防；服务端雷达投影是候选事实，页面访问不得创建行情订阅。
- `IOS-LUB-002`：待确认入场展示涨停价、距涨停档位、信号时间、过期时间、目标
  风险和退出模板；每次实盘批准均使用服务端预览和生物确认。
- `IOS-LUB-003`：展示成交后的 T+1、退出计划、部分退出、失败和 readiness；信号、
  买入确认和成交使用不同状态。

## 8. 资产与复盘

- `IOS-AST-001`：资产页展示总资产、可用/冻结资金、持仓市值、当日与累计盈亏，
  并提供可选择区间的资产/收益曲线和数据质量说明。
- `IOS-AST-002`：持仓按证券展示数量、可卖量、冻结、成本、现价、市值、盈亏、
  占比及“封存仓/核心仓/活跃仓”归因；归因不得替代券商真实持仓。
- `IOS-AST-003`：复盘展示策略贡献、已关闭持仓周期、交易结果、费用、决策原因和
  可追踪审计记录；数据不足时明确标注估算或不可用。

## 9. 通知

- `IOS-NTF-001`：APNs 覆盖待确认信号/退出、券商成交与拒单、策略/做 T/打板
  异常、清仓触发、Kill Switch、Agent 断线和关键数据过期；用户可按类别关闭，
  风险事件在 App 内仍必须保留。
- `IOS-NTF-002`：通知标题、正文和 payload 不含账户号、金额、持仓、订单明细或
  完整证券信息；payload 只携带随机事件 ID、类别和不含敏感参数的路由类型。
- `IOS-NTF-003`：点击通知后先本地解锁，再按当前会话重新查询对象；对象已处理、
  过期或账户不匹配时显示真实终态，不重放旧操作。

## 10. 安全、体验与可靠性

- `IOS-SEC-001`：原生会话使用设备作用域最小权限，通用 `mutation:write` 不得
  作为 iOS 写能力；每类读、交易、策略、助手和通知权限独立授权。
- `IOS-SEC-002`：所有账户型请求由服务端校验会话绑定主账户；响应出现其他账户
  数据时客户端整页拒绝展示并记录脱敏诊断。
- `IOS-SEC-003`：高风险确认挑战绑定用户、设备会话、账户、动作、规范化输入
  指纹和过期时间，只能使用一次；写操作使用幂等键。
- `IOS-SEC-004`：手动下单、清仓/实盘自动退出授权、助手买入批准和进入实盘模式
  逐次使用 Face ID/Touch ID；本地解锁不能替代交易确认。
- `IOS-SEC-005`：iOS 不接收或保存券商凭证、QMT 配置和设备密钥，不连接
  miniQMT，也不执行最终数量与合法性计算。
- `IOS-SEC-006`：每次允许、限量、拒绝、撤单、暂停、熔断和确认失败均可通过
  `requestId`、`traceId` 或业务事件 ID 追踪，日志不包含敏感原文。
- `IOS-SEC-007`：Agent 离线、行情/账户快照过期、对账异常、受控窗口失效或
  Kill Switch 时，客户端禁止新增实盘风险并准确展示阻断原因。
- `IOS-UX-001`：所有页面完整支持深浅色、最大无障碍字号、VoiceOver、Reduce
  Motion、44pt 触控区域和不依赖颜色的状态表达。
- `IOS-UX-002`：A 股采用红涨绿跌；价格、金额、数量和百分比使用等宽数字、明确
  单位和统一舍入，未知值显示“—/未知”而不是零。
- `IOS-UX-003`：所有页面覆盖加载、空数据、刷新失败、断网、权限不足、数据过期、
  部分成功和未知枚举，且保留最后有效内存快照时标明时间与原因。
- `IOS-REL-001`：冷启动、回前台、Token 轮换和 WebSocket 重连均先查询关键快照
  再恢复订阅；重复、乱序和旧序列增量不得回滚新状态。
- `IOS-REL-002`：记录客户端、API、Engine 和 Agent 关键时间点，能区分 UI、网络、
  服务端排队、Agent 投递和券商回报延迟。
- `IOS-REL-003`：Token、确认令牌、账号、完整持仓/订单、券商原文和通知内容不
  进入日志、崩溃报告、截图或诊断包；后台任务切换器始终显示隐私遮罩。

## 11. 发布需求

- `IOS-RLS-001`：每轮 Schema 或 operation 变化完成 Web/iOS 双端 codegen、契约
  diff、根测试、前端检查/测试/构建及 iOS 单元/UI 测试。
- `IOS-RLS-002`：完整产品通过 TestFlight 在真实 iPhone 上连续观察五个交易日，
  无 P0/P1 缺陷、崩溃、账户串读、敏感泄漏或错误成交语义。
- `IOS-RLS-003`：先完成全功能模拟盘，再在所有真实交易门禁显式满足后，进行
  单标的、100 股、人工监督灰度；自动化与普通 CI 始终禁止真实下单。

## 12. 明确不在 v1 范围

- 策略代码编辑、完整回测实验室、GA 进化和大规模参数研究。
- 数据源、数据库、Prefect、Agent 登记、QMT 路径或券商凭证管理。
- 多账户切换、多人共享账户、公开 App Store 分发、代客交易或社交功能。
- 融资融券、期权、期货、港美股、申购、转账和资金赎回工作台。
- 未经服务端能力声明的通用市价单、客户端自动选股或离线下单。
- 依赖后台常驻 WebSocket 的监控；APNs 只负责唤醒用户，不是状态真源。

## 13. 核心术语

| 用户文案 | 内部语义 |
| --- | --- |
| 封存仓 / 核心仓 / 活跃仓 | `locked_core / core / swing` 归因，不等于券商子账户 |
| 已排队 | pending order/outbox 已持久化，尚不代表 Agent 或券商已收到 |
| 已投递 | `command_ack`，只代表 Agent 收到命令 |
| 券商已报 | QMT 委托回报确认 `submitted/accepted` |
| 已成交 | QMT 成交回报经 inbox 持久化并由 Engine 收敛 |
| 准备中 | `SHADOW/PREPARING` 的观察与对账状态，不等于服务故障 |
| 自动交易就绪 | 所有受控窗口、白名单、快照、对账和授权门禁通过 |
