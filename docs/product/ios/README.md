[《QuantX 原生 iOS App 开发准备与实施计划》](../../plans/QuantX原生iOSApp开发准备与实施计划.md)

和现行 A 股交易域契约为准。

## 规范优先级

出现冲突时按以下顺序处理：

1. `AGENTS.md` 中的交易系统硬约束。
2. [A 股三层协作与执行契约](../../trading/contracts/A股三层协作与执行契约.md)、
   [A 股交易域数据结构与状态机](../../trading/contracts/A股交易域数据结构与状态机.md)
   和[自动退出计划契约](../../trading/contracts/A股自动退出计划与卖出策略契约.md)。
3. 本目录的产品、安全与验收要求。
4. 在线客户端接入文档 `apps/docs/content/`。
5. 旧计划和历史实现说明。

任何产品需求都不得授权 iOS 直接访问 QMT、计算最终合法订单数量、把
`command_ack` 当成券商受理或成交，或绕过 Engine、OrderSizer、交易域风控与
数据库消息箱。

## 稳定需求 ID

需求 ID 采用 `IOS-<DOMAIN>-NNN`，已发布 ID 永不复用或改义。删除的需求保留
原 ID 并标记 `RETIRED`；语义发生实质变化时创建新 ID。领域代码包括：

- `PLT`：产品与平台；`NAV`：导航；`TDY`：今日；`MKT`：行情。
- `TRD`：交易与卖出；`QNT`：策略；`TTR`：做 T；`LUB`：打板。
- `AST`：资产；`NTF`：通知；`SEC`：安全；`UX`：体验。
- `REL`：可靠性；`RLS`：发布。

新增或修改需求时，必须同时更新 PRD、追踪矩阵和受影响的验收项。GraphQL
字段、权限或原生会话模型变化时，还必须刷新发布契约和在线客户端文档。

## 状态口径

追踪矩阵中的实现状态使用以下固定值：

| 状态 | 含义 |
| --- | --- |
| `DONE` | 当前实现与自动化证据已满足需求 |
| `PARTIAL` | 已有可复用实现，但仍缺少目标行为或验收证据 |
| `GAP` | 当前客户端或服务端尚无目标能力 |
| `CONTRACT_GAP` | 已有相近能力，但公共接口或权限边界不足，禁止客户端绕过 |
| `BLOCKED` | 外部条件或明确决策阻断；必须记录负责人和解除条件 |

`DONE` 只能由测试与验收证据支持，不能因为页面存在、Mutation 返回成功或
开发环境能读取真实账户而宣告完成。

## 变更流程

1. 先在 PRD 增补或修订稳定需求，并说明兼容影响。
2. 同步交互、视觉、API/安全及验收文档。
3. 更新追踪矩阵的接口、权限、测试、证据和状态。
4. Schema 变化时通过 Caddy 运行 Web codegen，刷新客户端契约，并运行 Apollo
   iOS codegen；不得手改生成类型。
5. 产品范围冻结后才进入 TestFlight 发布候选；阶段性内部构建不等于产品验收。
