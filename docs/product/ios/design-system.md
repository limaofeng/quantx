# QuantX iOS 视觉设计系统

> 设计方向：原生、专业、克制、数据优先的个人量化终端
>
> 对应需求：`IOS-UX-001`、`IOS-UX-002`、`IOS-UX-003`

## 1. 设计原则

1. **先结论，再证据**：第一视区回答“要不要行动、风险是什么、结果怎样”。
2. **密度可控**：金融信息可以紧凑，但每个区块只保留一个主要层级和一个主操作。
3. **状态可信**：颜色、图标、文字、时间共同表达，未知状态不美化成正常。
4. **平台原生**：使用 SwiftUI 导航、Sheet、Toolbar、系统字体、SF Symbols 和
   系统手势，不复制桌面多窗格或网页侧边栏。
5. **风险克制**：买入、卖出、清仓、熔断和进入实盘具有不同语义，不用同一种
   强调色制造误操作。

## 2. Token

所有颜色和尺寸通过语义 Token 使用，业务 View 不直接写十六进制颜色或任意
间距。下表是 v1 基线；实现时必须通过浅色、深色和 Increase Contrast 验证。

### 2.1 颜色

| Token | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| `surface.canvas` | `#F5F7FA` | `#090D14` | 页面背景 |
| `surface.primary` | `#FFFFFF` | `#111722` | 卡片、Sheet |
| `surface.secondary` | `#EEF2F6` | `#192231` | 次级分组、输入背景 |
| `surface.elevated` | `#FFFFFF` | `#202B3A` | 浮层、菜单 |
| `text.primary` | `#111827` | `#F3F6FA` | 主文字 |
| `text.secondary` | `#526071` | `#AAB6C5` | 次文字 |
| `text.tertiary` | `#768396` | `#8290A3` | 时间、注释；小字号需另验对比度 |
| `border.subtle` | `#DDE3EA` | `#2B3747` | 分隔线、边框 |
| `brand.primary` | `#2457D6` | `#6F95FF` | 导航选择、普通主操作 |
| `market.up` | `#C92A36` | `#FF6670` | A 股上涨/盈利 |
| `market.down` | `#16804A` | `#42D58A` | A 股下跌/亏损 |
| `market.flat` | `#667085` | `#98A2B3` | 平盘/无变化 |
| `state.success` | `#137A48` | `#45D58D` | 非行情成功 |
| `state.warning` | `#A45A00` | `#F5B942` | 临期、降级、准备中 |
| `state.danger` | `#B42318` | `#FF6B61` | 阻断、拒绝、破坏性操作 |
| `state.info` | `#175CD3` | `#73A5FF` | 信息、处理中 |

行情涨跌色与通用成功/失败色分开，避免“卖出成功”和“下跌”共用相同语义。
任何彩色文字在其实际背景上至少满足 WCAG AA；不满足时使用更深/更浅变体，
不得通过降低字号规避。

### 2.2 字体与数字

使用 SwiftUI Dynamic Type 文本样式，不固定像素字号：

| 语义 | SwiftUI 样式 | 规则 |
| --- | --- | --- |
| 页面标题 | `.title2.weight(.semibold)` | 跟随系统导航时不重复大标题 |
| 关键资产 | `.title.weight(.semibold)` | 使用 `.monospacedDigit()` |
| 区块标题 | `.headline` | 一行，必要时允许换两行 |
| 正文 | `.body` | 不低于系统 Body |
| 标签/辅助 | `.subheadline` | 重要状态不可只用 Caption |
| 时间/脚注 | `.footnote` | 支持完整 Dynamic Type |
| 表格数字 | `.body.monospacedDigit()` | 小数点和位数按业务格式化 |

规则：

- 价格保留交易品种要求的小数位；金额以人民币格式化并明确“元/万元”。
- 百分比始终显示符号；数量使用“股”，不得把 `nil` 格式化为 0。
- 账号只显示末四位；主界面不显示完整账号。
- 无法确认口径时显示“—”或“未知”，并提供原因，不显示 `0.00`。

### 2.3 间距、圆角与尺寸

采用 4pt 基础网格：`space.1=4`、`2=8`、`3=12`、`4=16`、`5=20`、`6=24`、
`8=32`。页面水平边距 16pt；相邻同组行间距 8pt，不同区块 20–24pt。

- 标准卡片圆角 12pt，输入与小按钮 10pt，状态胶囊使用全圆角。
- 最小触控区域 44×44pt；列表行最小高度 48pt。
- 1px/1pt 分隔线使用 `border.subtle`；不以多层阴影模拟桌面面板。
- Modal Sheet 优先使用系统 detent；交易预览默认大尺寸，不能在半屏截断风险信息。

## 3. 信息层级与布局

### 3.1 页面模板

```text
Navigation title + toolbar
Data freshness / blocking banner (only when needed)
Primary insight or action
Core content sections
Secondary details / audit
Safe-area-aware bottom action (when applicable)
```

列表优先使用系统 `List`/`Section` 或语义等价组件。卡片只用于需要整体点击、
比较或突出结论的对象，不能给每一行数据都套独立大卡片。

### 3.2 金融数据行

标准行情/持仓行分为三列：

- 左：证券名称和代码/状态。
- 中：现价、成本或策略状态。
- 右：涨跌幅、盈亏或主要动作，数字右对齐。

无障碍字号下改为垂直布局，阅读顺序仍是名称 → 主要数值 → 状态 → 操作；不
允许横向滚动才能读到核心数值。

## 4. 核心组件

### 4.1 `FreshnessBanner`

状态：`fresh`（默认隐藏）、`delayed`、`stale`、`offline`、`unknown`。展示最后
成功时间、原因和刷新操作。交易页面处于 `stale/offline/unknown` 时由服务端能力
决定只读，客户端不能仅隐藏横幅后继续提交。

### 4.2 `StatusBadge`

徽标必须同时包含图标和文字。固定语义：

| 状态族 | 图标建议 | 示例 |
| --- | --- | --- |
| 正常/完成 | `checkmark.circle.fill` | 已成交、运行正常 |
| 处理中 | `clock.arrow.circlepath` | 已排队、撤单中 |
| 警告/准备 | `exclamationmark.triangle.fill` | 数据延迟、准备中 |
| 阻断/失败 | `xmark.octagon.fill` | 风控拒绝、Kill Switch |
| 未知 | `questionmark.circle` | 未知券商状态 |

“上涨/下跌”不用完成/失败图标；用箭头、正负号和红绿行情色表达。

### 4.3 `MetricTile`

由标题、主数值、变化、口径、更新时间组成。今日页首屏最多四个，不允许连续
堆叠多个只有一个数字的大卡片。隐私模式下数字替换为等宽占位，不改变布局。

### 4.4 `ActionInboxRow`

包含风险图标、标题、原因、对象类型、截止时间和一个主操作。风险排序由服务端
事实与本地展示规则共同完成，不能仅按颜色排序。过期后按钮变为“查看结果”。

### 4.5 `OrderTicket` 与 `TradePreviewSheet`

- 票据使用标准表单组件，方向分段控件保持红涨绿跌以外的中性选择样式。
- “预览订单”使用 `brand.primary`；确认实盘操作使用明确文字，不只显示图标。
- 卖出使用中性或品牌主色，清仓与 Kill Switch 使用 `state.danger`。不要把所有
  卖出按钮都做成危险红色，以免与上涨色混淆。
- 预览 Sheet 以只读键值行展示规范化结果，警告位于按钮之前；确认令牌永不显示。
- 生物确认按钮文案为“Face ID 确认并提交”或“Touch ID 确认并提交”，按当前
  设备能力生成；不可用时不降级为普通按钮。

### 4.6 `OrderTimeline`

节点至少覆盖：已排队、已投递、券商已报、部分成交、已成交，以及拒绝/撤单/
过期分支。每个节点显示来源和时间；`command_ack` 节点文案只能是“已投递”。
部分成交节点展示累计成交量，不为每条重复回报增加新节点。

### 4.7 `RiskGateCard`

分为 `ready/preparing/blocked/killSwitch`。展示结论、最多三个主要原因和“查看全部
检查”。`PREPARING` 使用 warning 而不是 danger；自动交易未授权不能渲染成服务
离线。阻断状态中的按钮只能是修复/查看，不提供强制绕过。

### 4.8 空态、错误与权限态

- 空态：简洁图标、事实描述、一个可执行下一步。
- 权限态：锁图标、能力名称、当前只读范围；不要求用户在 App 内找管理员。
- 错误态：中文说明、是否可重试、脱敏 `requestId` 复制按钮。
- 部分失败：用逐项列表，不用一个 Toast 覆盖所有结果。

## 5. 图表规范

### 5.1 分时与 K 线

- 分时展示价格、昨收参考线和成交量；午间休市不连接成连续交易。
- K 线默认日 K，涨/跌沿用 A 股红/绿；提供日期、开高低收、成交量的可访问
  selection，不把十字线作为唯一读数方式。
- 数据断档、过期或未复权口径变化使用可见标记和说明，不能插值伪造。
- 涨跌停、停牌与集合竞价使用背景/标记加文字，不仅使用颜色。

### 5.2 资产曲线

- 资产与收益使用不同单位时不共用无说明的双轴。
- 区间首尾和选中点显示日期、资产、净入金和收益口径；数据质量不足时显示
  `estimated/incomplete` 标签。
- 用户选择 Reduce Motion 时关闭入场动画；更新数据不让曲线整体闪烁。

### 5.3 VoiceOver

图表整体提供摘要，例如“近一月收益上涨 3.2%，最低点 8 月 3 日”；可选点按日期
顺序访问。装饰线、网格和点不单独进入可访问性树。

## 6. 反馈与动效

- 点击后 100ms 内出现高亮、进度或禁用反馈；网络请求期间保留上下文。
- 普通刷新使用系统进度；交易确认使用明确阶段文字，不使用无限旋转替代状态。
- Toast 只用于低风险、无需后续处理的结果；订单、撤单、清仓和策略控制进入
  持久状态行或详情页。
- Reduce Motion 下取消位移动画、数字翻牌和图表绘制动画；保留必要淡入淡出。
- 成交、盈利或进入实盘不使用烟花、彩带、震动庆祝等游戏化反馈。

## 7. 深浅色与截图隐私

深色不是简单反色。图表、盘口、风险卡、输入、Sheet 和导航分别验证前景/背景
对比度。OLED 深色仍保留层次，不使用大面积纯黑加高饱和红绿。

进入非活动态或系统生成任务切换快照前，根窗口覆盖不透明隐私页；内容至少覆盖
账户、资产、持仓、证券、订单和图表。系统截图无法从应用层完全禁止，因此测试
证据、诊断附件和文档截图必须使用脱敏数据并存放于 `.codex_screenshots/`。

## 8. 无障碍验收基线

- 支持从标准字号到最大 Accessibility Dynamic Type，不截断主要操作和金额。
- 所有交互控件有效命中区域不小于 44pt；按钮名称包含动作和对象。
- VoiceOver 阅读顺序与视觉任务顺序一致，状态变化通过可控 announcement 提示。
- 涨跌、买卖、风险和状态均有颜色之外的文字/符号。
- 开启 Increase Contrast、Button Shapes、Reduce Motion 后仍能完成全部 P0 流程。
- 最小受支持 375×667pt 和最大 Pro Max 尺寸均无不可达控件；横屏不是 v1 必需
  布局，但旋转不得导致崩溃或敏感快照泄漏。
