# QuantX iOS 信息架构与交互规范

> 对应需求：`IOS-NAV-*`、`IOS-TDY-*`、`IOS-MKT-*`、`IOS-TRD-*`、
> `IOS-QNT-*`、`IOS-TTR-*`、`IOS-LUB-*`、`IOS-AST-*`、`IOS-NTF-*`

## 1. 导航模型

底部 Tab 固定为以下顺序。切换 Tab 保留各自导航栈；退出登录、主账户变化或
会话被吊销时清空所有导航栈和业务状态。

| Tab | SF Symbol 建议 | 首屏任务 | 二级入口 |
| --- | --- | --- | --- |
| 今日 | `sparkles.rectangle.stack` | 找到今天必须处理的行动与风险 | 待办、告警、策略/助手摘要 |
| 行情 | `chart.xyaxis.line` | 找股票、看行情、形成交易上下文 | 搜索、自选、股票详情、图表、盘口 |
| 交易 | `arrow.left.arrow.right.square` | 下单、撤单、卖出管理、追踪结果 | 下单票据、委托、成交、退出计划 |
| 量化 | `waveform.path.ecg.rectangle` | 控制策略、做 T 和打板 | 策略详情、参数、批次、候选、审计 |
| 资产 | `chart.pie.fill` | 查看组合、持仓归因和复盘 | 持仓详情、收益曲线、复盘、设置 |

设置从资产页右上角账户头像进入。交易、量化或资产详情可互相深链，但不得为了
跳转而复制同一业务状态；返回后保持来源 Tab 的导航上下文。

### 1.1 稳定路由

Swift 路由应使用带关联值的类型，不用字符串拼接。以下是产品层稳定路由键，
实现可以重命名 Swift 类型，但 APNs 路由类型和测试标识必须保持兼容。

```text
today.action(eventId)
today.alert(alertId)
market.search
market.instrument(instrumentCode)
trade.ticket(instrumentCode?, side?)
trade.order(orderId)
trade.trade(tradeId)
trade.exitPlan(planId)
trade.liquidation(scope)
quant.strategy(instanceId)
quant.strategyParameters(instanceId)
quant.tTrade(accountId)
quant.tTradeBatch(batchId)
quant.limitUp(accountId)
quant.limitUpIntent(runId, intentId)
assets.position(instrumentCode)
assets.review(referenceId)
settings.root
settings.notifications
settings.sessions
```

外部深链只接受事件 ID 和路由类型。它不能携带账号、价格、数量、确认令牌或
直接执行动作。路由解析顺序固定为：恢复/刷新会话 → 本地解锁 → 校验主账户 →
按 ID 重新查询 → 展示当前终态。

## 2. 全局页面结构

每个业务页面从上到下采用相同层级：

1. 导航标题与全局刷新/账户入口。
2. 数据新鲜度和阻断横幅；正常且新鲜时不占用大面积空间。
3. 关键结论或主要操作。
4. 支撑结论的数据、解释和次级操作。
5. 审计、更新时间与帮助。

### 2.1 通用状态

| 状态 | 页面行为 |
| --- | --- |
| 首次加载 | 使用与最终布局一致的骨架，不显示虚构数值 |
| 空数据 | 说明为什么为空，并仅在有权限时给出下一步 |
| 刷新失败但有旧快照 | 保留快照，顶部显示“数据截至 HH:mm:ss”及失败原因 |
| 无可用快照 | 显示阻断页；交易主操作不可用 |
| 权限不足 | 说明缺少的产品能力，不展示可点击但必然失败的控件 |
| 部分成功 | 逐项列出成功、失败和未知，不把批量操作压成单一成功提示 |
| 未知枚举 | 显示“未知状态”与原始时间，禁止猜测更有利的状态 |
| 跨账户数据 | 整页拒绝显示，清空该 Feature 内存状态并生成脱敏诊断 ID |

全屏错误只用于没有任何可用信息的情况。局部模块失败不应抹除同页其他可信
数据；刷新也不应把最后有效内存快照先清空。

## 3. 今日

今日页不是服务监控面板，内容按以下优先级动态排序：

1. **必须立即处理**：待确认且即将过期的交易/退出、Kill Switch、无法解释的
   对账差异、实盘受控窗口失效。
2. **需要关注**：拒单、撤单失败、策略异常、Agent 断线、行情/快照过期。
3. **进行中**：未完成委托、部分成交、DRAINING、活动做 T 批次、退出计划。
4. **结果摘要**：今日成交、已完成动作、当日盈亏。
5. **系统摘要**：策略、助手和数据服务状态。

### 3.1 首屏组成

- 账户摘要：总资产、当日盈亏、可用资金、持仓市值；支持隐私眼睛按钮。
- 行动收件箱：按风险、过期时间、发生时间排序，最多展示五项并提供“全部”。
- 交易进度：活动委托和部分成交；点击进入订单详情。
- 量化摘要：策略运行/暂停/异常数量、做 T 待确认/活动批次、打板候选/待确认。
- 风险与连接：只在非正常时展开；正常状态使用一行紧凑摘要。

行动项的主文案回答“发生了什么”，副文案回答“为何需要我处理”，尾部显示
截止时间或最新状态。过期项的主按钮替换为“查看结果”，不能继续提交旧确认。

## 4. 行情

### 4.1 行情首页

默认展示“自选”，可切换“持仓”。顶部搜索支持代码、简称和拼音首字母；搜索
结果至少显示代码、名称、市场、最新价、涨跌幅和交易状态。

自选编辑规则：

- 滑动删除前不需要生物识别，但必须等待服务端确认后再固化排序。
- 拖动排序采用乐观 UI；写入失败恢复服务端顺序并提示，不产生重复项。
- 同一证券在同一账户自选中唯一；客户端不通过本地去重掩盖服务端异常。

### 4.2 股票详情

固定顺序：行情头部 → 分时/K 线 → 五档盘口与逐笔 → 当前持仓 → 相关策略/计划
→ 相关委托成交。

- 行情头部明确显示市场阶段、停牌/风险标识、涨跌停价和最新时间。
- 图表周期至少支持分时、日 K、周 K；更多周期只能由真实 API 支持后开放。
- 五档缺失时显示“盘口不可用”，不以空白行或 `0.00` 补齐。
- 底部操作栏提供“买入”“卖出”和“量化”；卖出仅在存在持仓时可用。
- 进入票据只预填标的与方向。价格可以以当前行情作为可编辑参考，数量不自动
  推导；最终合法价格和数量由服务端预览确认。

## 5. 交易

交易首页采用顶部分段选择：“下单”“委托”“成交”“卖出管理”。切换分段不
改变底部 Tab，不用多个重复的 Tab Bar。

### 5.1 手动下单票据

字段顺序固定：

1. 标的：代码、名称、市场、交易状态和数据时间。
2. 方向：买入/卖出，不允许在确认页悄悄改变。
3. 报价类型：限价或服务端能力允许的“对手方最优价”。
4. 价格：仅限价显示；支持合法 tick 的加减按钮。
5. 数量：股数输入和常用比例快捷键。比例只计算草稿，服务端决定合法数量。
6. 账户事实：可用资金或可卖量、冻结量、涨跌停和风险提示。
7. “预览订单”主按钮。

输入校验分层：客户端即时校验格式与明显错误，服务端预览校验所有交易规则。
客户端校验通过不表示订单合法。

### 5.2 预览与确认

```text
编辑票据
  -> 请求服务端预览
  -> 展示规范化后的方向、报价、合法数量、金额、费用、行情时间和警告
  -> 用户点击“Face ID / Touch ID 确认”
  -> LocalAuthentication 成功
  -> 消费短时确认挑战
  -> 显示“已排队”及 clientOrderId
  -> 进入订单详情等待券商回报
```

预览页不可编辑。用户要修改任一字段必须关闭预览并重新请求；挑战过期、价格
漂移、账户快照更新或门禁变化均返回票据并保留草稿，不重放确认请求。

确认成功页只能使用“订单已排队，等待下发”，并直接展示当前状态时间线。
禁止使用“下单成功”“交易成功”或庆祝动效。

### 5.3 委托详情与撤单

订单详情包含：标的、方向、报价、委托量、成交量、剩余量、成交均价、来源、
客户端订单 ID、券商订单 ID（可用时）、状态时间线和拒绝原因。

撤单交互：

1. 仅服务端 `canCancel=true` 时展示“撤单”。
2. 二次系统 Alert 展示剩余量和“撤单不保证阻止已在途成交”。
3. 提交后按钮进入不可重复点击状态，文案为“撤单请求已提交”。
4. 只有券商回报 `CANCELED` 才显示“已撤”；期间仍处理部分或全部成交。
5. 撤单不要求生物确认；撤单失败保留原委托状态和可审计原因。

### 5.4 卖出管理

卖出管理包含“退出计划、持仓清仓、卖出历史”，与统一 ExitPlan 模型一致。

单只/选中/全仓清仓流程：

```text
选择范围
  -> 选择 AVAILABLE_NOW 或 UNTIL_SNAPSHOT_CLEARED
  -> 选择 UNALLOCATED_ONLY 或 REPLACE_CANCELLABLE 冲突策略
  -> 服务端生成逐证券预览
  -> 展示纳入/跳过/不可卖/冲突/已有待成交 SELL
  -> 生物确认实盘授权
  -> 创建计划/待确认 SELL
  -> 逐计划追踪委托与成交
```

全仓入口位于“卖出管理 > 持仓清仓 > 全部持仓”，使用破坏性样式，但不得把
无可卖量或冲突持仓从预览中隐藏。全仓确认只覆盖预览快照，后续新持仓明确
显示“未纳入本次清仓”。

条件退出计划编辑顺序：保护数量 → 触发规则 → 数量策略 → T+1 策略 → 委托偏好
→ 模拟/实盘授权。实盘自动授权必须展示有效期和精确规则；规则或保护量变化会
使旧授权失效并要求重新预览、生物确认。

## 6. 量化

量化首页固定三段：“策略”“做 T”“打板”。每段顶部先展示风险/就绪状态，
再展示实例或候选。

### 6.1 策略生命周期

策略详情主操作由服务端 capability 和状态决定：

| 当前状态 | 可展示操作 | 关键限制 |
| --- | --- | --- |
| STOPPED | 启动 | 实盘启动需 readiness 预览和生物确认 |
| RUNNING | 暂停、停止入场 | 有活动退出计划时进入 DRAINING |
| PAUSED | 恢复、停止入场 | 恢复实盘前重新校验 readiness |
| DRAINING | 查看退出进度 | 不允许新增 BUY，不表示保护已停止 |
| ERROR/BLOCKED | 查看原因、允许的恢复 | 不提供绕过门禁的强制启动 |

普通暂停/停止入场使用确认 Alert；进入实盘、实盘启动或提高实盘风险必须使用
服务端预览和生物确认。Mutation 返回后重新查询实例，不在本地先假定终态。

参数页只渲染服务端 `mobileEditable` 描述：显示名、说明、类型、单位、范围、
步长、当前值和配置版本。保存时提交 `expectedVersion`；版本冲突后保留用户
草稿并以差异页让用户重新核对，禁止自动覆盖。

### 6.2 做 T

做 T 首页依次显示：总开关/模式 → readiness 与 Kill Switch → 待确认信号 →
监控持仓与忽略列表 → 活动批次 → 历史。

- 待确认卡片的倒计时来自服务端过期时间；本地时间异常时保守禁用确认。
- 批次详情分开显示入场和退出的委托/成交，净收益注明费用口径。
- 有活动批次时“停止”根据服务端返回进入 DRAINING，不能清除退出保护。
- Kill Switch 是最高优先级危险操作：显示影响范围，经生物确认触发；触发成功
  只表示服务端接受熔断动作，进行中订单仍按回报展示。

### 6.3 打板

打板首页依次显示：readiness/风险预算 → 待确认意图 → 当日已布防 → 候选雷达 →
持仓与退出计划。

- 候选列表显示阶段、涨停价、距涨停档位、首次触板/回封次数和数据时间。
- 布防/取消布防不是下单，不使用“买入”文案；写入失败恢复服务端状态。
- 买入意图批准复用统一交易预览；预览必须包含退出模板和 T+1 提示。
- 已封死、一字板、行情过期、已有持仓/计划或风控禁买时只展示服务端原因。

## 7. 资产与设置

### 7.1 资产

资产页顺序为：账户总览 → 资产/收益曲线 → 仓位结构 → 持仓 → 策略贡献 → 复盘。

- 曲线支持 1 周、1 月、3 月、今年、全部；服务端数据不足时缩短区间并标注。
- 持仓默认按市值降序，可切换盈亏、涨跌、代码；排序只影响展示。
- 持仓详情同时显示券商数量/可卖量和 bucket 归因，二者不一致时展示数据质量，
  不强行把 bucket 相加结果写成真实持仓。
- 复盘以已关闭持仓周期、策略贡献和 DecisionTrace 为入口，估算收益必须标明。

### 7.2 设置

设置包含：当前用户与脱敏主账户、环境、设备会话、通知偏好、本地生物锁、隐私
遮罩、外观、诊断、版本和退出登录。不得包含 QMT 登记、券商凭证或服务端运维。

“退出所有设备”与普通退出登录分开；本地登出无论远端请求是否成功都清理
Keychain、Apollo Store、通知路由和内存状态，并提示远端吊销是否成功。

## 8. 通知与行动收件箱

通知类别和默认值：

| 类别 | APNs 默认 | App 内保留 | 示例（不含敏感信息） |
| --- | --- | --- | --- |
| 待确认 | 开 | 是 | “有一项量化交易等待确认” |
| 委托成交 | 开 | 是 | “一笔委托状态已更新” |
| 风险与熔断 | 开 | 是 | “交易安全状态需要处理” |
| 策略/助手异常 | 开 | 是 | “一项量化任务出现异常” |
| 连接与数据 | 关 | 是 | “关键数据连接已中断” |

v1 使用普通 APNs，不申请 Critical Alerts。推送被关闭、延迟或丢失不影响 App 内
行动收件箱；打开 App 时总是从服务端查询当前待办和终态。

## 9. 文案红线

| 事实 | 允许文案 | 禁止文案 |
| --- | --- | --- |
| 预览已生成 | 待确认、预览有效至… | 订单已创建 |
| 确认 Mutation 成功 | 已排队、等待下发 | 下单成功、交易成功 |
| `command_ack` | Agent 已收到 | 券商已报、已成交 |
| 委托回报 accepted | 券商已报 | 已成交 |
| 部分成交 | 已成交 X / Y 股 | 成交完成 |
| 取消命令已排队 | 撤单请求已提交 | 已撤单 |
| SHADOW/PREPARING | 观察与对账准备中 | 系统故障、实盘已就绪 |
| 策略 BUY 信号 | 买入信号、待确认 | 买入、持仓已增加 |

服务端返回的内部 reason code 需要映射为中文解释，同时在详情页保留可复制的
`requestId/traceId`；不得把异常堆栈或原始券商响应展示给用户。
