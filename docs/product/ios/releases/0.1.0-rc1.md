# QuantX iOS 0.1.0-rc1 发布候选报告

> 报告日期：2026-08-15
>
> 源码基线：iOS 集成提交 `7bb2fc1`；版本 `0.1.0`，构建号 `1`。文档冻结点
> 以包含本报告的 Git 提交为准；发布签名、Archive 与 TestFlight 构建尚未生成。
>
> 发布结论：**NO-GO / `BLOCKED`**。本版本只能用于继续开发和自动化收口，
> 不得发布到个人生产设备，不得开启实盘 capability。

## 1. 结论摘要

产品方向已经从“移动监控端”纠正为“单用户、单主账户的个人 A 股量化 iOS
控制中心”。五 Tab、唯一账户会话、行情/自选、PAPER-first 手工下单、撤单、
清仓、策略安全参数与实盘挑战、ExitPlan 精确授权、做 T rollout/Kill Switch、
APNs 服务端和客户端基础均已有实质实现及针对性自动化证据。

这不等于产品已成熟或已达到发布条件。当前至少存在以下硬缺口：

- ExitPlan 的 v1 创建/编辑交互尚未完成；策略 stop/DRAINING 未形成完整契约与 UI。
- 资产/收益区间曲线、bucket 归因、策略贡献和完整复盘尚未完成。
- 做 T 完整设置、打板完整移动闭环和端到端可观测时间线不完整。
- 完整 pytest collection、可运行测试集、全量 Ruff 和 Web 公共 endpoint codegen
  没有形成全绿证据。
- 没有真实 APNs、全功能 paper、做 T/打板各 20 个闭环、真实设备无障碍矩阵、
  五日 TestFlight 或受控实盘证据。

因此[追踪矩阵](../traceability.md)没有任何条目标记为 `DONE`。

## 6. 安全与回滚声明

- RC1 验证不运行真实交易，不能使用 `data-only` 冒充完整开发实盘能力，也不能
  为验证而启动普通默认 `full/live` 环境。
- APNs Worker 默认关闭；没有凭据时保持关闭，通知缺失不能影响 App 内业务事实。
- 未完成 Canary 的手工交易、清仓、策略、做 T、打板 capability 由服务端关闭；
  不能用客户端隐藏按钮代替权限和 readiness。
- 发生账户串读、重复/错误订单、假成交、明文挑战或敏感泄漏时，立即按 P0：关闭
  对应 capability、吊销设备会话、停止新增风险，保留 outbox/inbox/券商回报继续
  收敛和审计；不得删除在途订单或伪造终态。
