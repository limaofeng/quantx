# QuantX 个人 A 股量化 iOS 开发路线图

> 路线原则：按依赖顺序合并、按阶段内部验收，所有目标能力完成后统一进入正式
> TestFlight 发布门禁；不把功能残缺的阶段构建描述为最终产品。

## 1. RC1 实施基线（2026-08-15）

当前工程已经完成产品方向纠偏：原生主导航固定为“今日/行情/交易/量化/资产”，
会话保存专用 scope、唯一主账户从授权关系实时解析；行情、自选、PAPER-first 手工订单、撤单、
单只/选中/全仓清仓、策略移动参数和实盘控制均已有实现。服务端同时落地了
ExitPlan 精确自动退出授权、设备绑定做 T rollout/Kill Switch、APNs 持久投递与
业务事件投影；iOS 通知、策略、ExitPlan 和做 T 工作区已在 `7bb2fc1` 完成统一
codegen、集成与自动化验证。

`0.1.0-rc1` 仍不是可发布版本。ExitPlan 创建/编辑、策略 stop/DRAINING、资产
区间曲线与策略贡献、打板完整移动闭环、端到端可观测性尚未完成；真实 APNs、
全功能 paper、做 T/打板各 20 个闭环、真实设备无障碍矩阵、五日 TestFlight 和
受控实盘均没有证据。Web 已从远端 Caddy 公共端点完成权威 codegen 且生成物无
差异，但完整 pytest/Ruff 仍未形成全绿发布记录。权威状态见
[追踪矩阵](traceability.md)和
[RC1 发布报告](releases/0.1.0-rc1.md)。

## 2. 里程碑与依赖

```text
M0 规格与契约基线
  -> M1 App 壳层、设计系统、会话与权限
      -> M2 今日、行情、资产（可信读取面）
          -> M3 手动交易与卖出管理（交易写入面）
              -> M4 策略、做 T、打板（量化控制面）
                  -> M5 APNs、可靠性与可观测性
                      -> M6 全量 TestFlight 与受控实盘发布
```

M2 的行情/账户新鲜度、M1 的设备 scope 和 M0 的挑战契约是 M3/M4 的硬依赖。
APNs 可以在 M3/M4 后半并行开发，但 M5 必须基于已经稳定的事件 ID 和路由。

## 3. M0：规格与契约基线

> RC1 状态：`IMPLEMENTED_AUTO`。文档与核心契约已实现，不能代替最终产品、
> 安全和发布负责人签署。

### 交付

- 冻结本目录文档、稳定需求 ID 和追踪矩阵。
- 完成公共 GraphQL 差距清单：设备 scope、唯一主账户、专用权限、订单 capability、
  手动订单/清仓预览确认、参数 allowlist、策略控制挑战和 APNs。
- 为新增 Input/Result、权限和错误码写服务端契约测试，再实现 Resolver。
- 标记旧只读计划被取代，更新在线客户端快速开始、权限和订单语义。

- Web 兼容范围明确；iOS 不会通过现有 `mutation:write` 接口暂时绕过。

## 4. M1：App 壳层、设计系统、会话与权限

> RC1 状态：`IMPLEMENTED_AUTO`。主要代码和针对性自动化成立；完整真实设备、
> 最大字号、VoiceOver 与 Accessibility Audit 仍属于 M6 前置证据。

### 服务端

- 原生登录只接受用户名、密码和设备名；服务端绑定唯一授权账户，并在
  `user.permissions` 返回 iOS 能力白名单交集，刷新只允许缩权。
- GraphQL iOS 写字段映射到专用 scope；Web 与 iOS 各自使用唯一明确的权限契约。
- 提供客户端 capability 投影，后端未部署时高风险功能自然不可用。

### iOS

- 把主导航重构为今日/行情/交易/量化/资产，建立类型安全 Route 和通知路由解析器。
- 以 Design Token 重建颜色、字体、间距、状态、错误、Freshness、金融数字、
  订单时间线、风险门禁和图表基础组件。
- Feature Store 按主账户隔离；统一处理权限、快照、stale、部分失败和未知枚举。
- 保留并收紧 Keychain、刷新并发去重、隐私遮罩、本地解锁和登出清理。

### 测试与出口

- 会话 scope/账户/吊销矩阵、五 Tab 路由、深浅色、最大字号和隐私测试通过。
- 只有正确 scope 的会话能构造对应 Repository；宽泛 `mutation:write` 不解锁 UI。
- M1 完成不发布，只提供空态/只读开发壳供 M2 使用。

### 打板

### 阶段出口

## 11. 合并、迁移与回滚策略

### 11.1 合并

- 每个里程碑按“服务端契约与测试 → 公共契约/codegen → iOS Domain/Repository →
  UI/UI 测试 → 文档矩阵”顺序合并。
- 同一 Schema 变更轮次完成 Web/iOS 双端生成和验证，不长期提交无法消费的半套契约。
- 内部功能开关只反映服务端 capability，不创建能绕过权限或风险门禁的本地开关。

### 11.2 契约迁移

- 会话契约在服务端、公共 OpenAPI、iOS、文档和测试中原子切换；退休字段直接
  拒绝，不增加双协议、可选兼容字段或只读兜底。
- iOS 从第一天只使用专用权限；Web 使用其独立权限契约，不把宽泛 Mutation
  权限映射为 iOS 能力。
- 新两阶段接口不改变已有 pending/outbox/Engine/QMT 状态流，不做第二套移动交易
  订单表或客户端专用成交状态机。
- 数据库迁移仅追加、可回滚代码读取，保留现有订单、成交、策略、ExitPlan、bucket
  和审计记录。

### 11.3 回滚与紧急处置

- App 版本回滚不能撤回已签发会话能力；服务端必须能按 capability/scope 立即关闭
  手动交易、清仓、策略控制、助手或通知注册。
- 发生 P0 时优先触发账户/功能 Kill Switch、吊销设备会话并停止新增风险；不删除
  在途订单或伪造终态，继续消费券商回报并对账。
- 回滚后仍保留审计、消息箱、计划和挑战使用记录；确认 Token 本身不保留明文。

## 12. 完成定义

某项需求只有同时满足以下条件才可在追踪矩阵标记 `DONE`：

- 产品和交互行为符合稳定需求，无隐式未决设计。
- API、权限、账户、错误、幂等和审计契约落地。
- App 覆盖加载、空、错、旧、权限、部分成功和未知状态。
- 自动化测试通过，适用的 paper/真机/实盘证据已附在发布报告。
- 相关在线文档、Schema、生成代码和用户文案同步。

仅完成代码、模拟器截图或 happy path 均不满足完成定义。
