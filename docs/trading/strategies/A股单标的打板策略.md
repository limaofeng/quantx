# A 股单标的打板策略

## 1. 定位

`AshareLimitUpBoardStrategy` 是固定单标的、long-only 的超短线入场策略。它
只负责识别临近涨停的扫板机会并输出 BUY `TradeIntent`；真实数量、交易时段、
100 股、现金、涨跌停、停牌、T+1、订单状态和成交收敛继续由公共交易域负责。

系统默认不模拟无法可靠成交的封板排队：

- 最新价距离涨停价 1 个最小价位时可以产生扫板意图。
- 最新价已经到达涨停价时输出 `limit_up_already_sealed`，不提交新意图。
- 回测与实盘都不能把涨停挂单或 `command_ack` 当作成交。

## 2. 入场条件

策略只在 `TICK` cadence 下决策，并要求同时满足：

1. 运行只绑定一个 `.SH` 或 `.SZ` 标的。
2. 行情提供明确的当日涨停价和最小价格变动单位。
3. 标的未停牌、不是 ST、没有退市风险，数据质量满足配置。
4. 当前处于配置的入场时间窗口，价格距离涨停价不超过
   `entry_distance_ticks`，且尚未封板。
5. 环境评分、累计成交额和买一量满足可选过滤条件。
6. 前置风控、仓位 profile 和执行 profile 均允许 `swing` 买入。
7. 当前没有真实持仓、未完成买单、待处理入场意图或活跃退出计划。
8. 未超过 `max_entry_attempts_per_day`。

输出意图使用：

```text
direction = BUY
bucket = swing
reason = limit_up_board_entry
limit_price_hint = 当日涨停价
target_position_pct = 配置目标与所有风险/profile上限的最小值
```

默认 `entry_execution_mode=MANUAL_CONFIRM`。设为 `AUTO` 也不会绕过统一后置
风控、实盘启用开关和 QMT Agent 本地保护。

人工确认使用 `approval_ttl_ms`，确认后限价委托使用独立的
`entry_order_ttl_ms`。委托超时后，回测 Broker 会在下一条行情撮合前将其
标记为 `EXPIRED`；paper/live 只请求撤单，最终状态仍以真实 broker 回报为准。
这可以避免信号已经失效后继续追入。

## 3. 前端打板工具

策略实例创建页会为该策略启用专属配置面板：

- 按入场、风险、确认与委托、退出、回测撮合分组展示完整参数。
- 固定单标的绑定，并在保存前检查入场时段、仓位上限和回测资金。
- 回测起止日期按浏览器本地交易日序列化为当天 `00:00:00.000` 和
  `23:59:59.999`，不经过 UTC 日期转换，避免东八区日期前移。
- 默认展示人工确认、一字板保护、退出授权与订单有效期。
- 回测模式额外启用 Tick 撮合、费用、滑点、成交量参与率、盘口深度参与率
  和严格数据门禁。
- 实盘模式必须绑定当前账户；创建实例时固定保持停止状态，用户需要进入
  实例详情页再次明确确认才可启动。
- 保存和启动操作带提交中锁，避免重复点击创建多份实例或回测；GraphQL
  业务失败和网络失败都在表单或工作台中明确显示。

实例详情页提供“打板工作台”：

- paper/live 展示待确认信号、剩余确认时间，并支持确认或拒绝。
- 展示真实成交后创建的退出计划、剩余数量、收益峰值、T+1 和触发规则。
- 回测展示涨停买入阻塞、跌停卖出阻塞、停牌、盘口限量、部分成交、
  未成交量和委托过期次数。
- 最近信号链路关联意图、订单和成交状态，不把已提交或已确认展示为成交。

## 4. 成交后退出

BUY 意图在 `metadata.exit_plan_template` 中携带退出模板。只有真实 BUY
`TradeExecutionEvent` 才会激活计划：

| 优先级 | 规则 | 数量 |
|---|---|---|
| 1000 | `LIMIT_UP_BREAK`：达到并持续封板后跌破配置价位 | 全部剩余 |
| 700 | `TRAILING_PRICE_DRAWDOWN`：达到启动收益后从峰值回撤 | 默认剩余量的 50%，一次 |
| 600 | `MAX_HOLDING_DAYS`：默认下一交易日 14:50 仍未退出 | 全部剩余 |

退出计划固定使用 `WAIT_UNTIL_SELLABLE`，不隐式借用其他 bucket 做 T+1 库存
置换。退出限价参考买一价。实盘只有 `auto_exit_authorized=true` 时允许自动
路由，否则 Engine 将退出意图降级为人工确认。

## 5. 状态与审计

策略只持久化算法状态：

- 当日尝试次数。
- 待处理入场意图 ID 和状态。
- 最近信号时间、价格。
- 最近真实入场成交日期、价格和数量。

拒单、撤单和过期只清理 pending，不伪造成交；买入成交量和退出计划的剩余
数量由 broker 回报与 `ExitPlanBook` 管理。每次不入场都通过
`decision_tags` 和 `trace_payload.reason` 保存结构化原因。

## 6. 回测口径

打板策略回测默认设置 `auto_approve_manual_intents=true`。它只在
`BACKTEST` 模式下将人工信号自动送入同一订单状态流，不影响 paper/live 的
人工确认语义。回测撮合同时应用：

- A 股涨跌停、停牌、T+1、整手和费用规则。
- 可执行盘口深度参与率；没有完整盘口时使用行情成交量参与率。
- `entry_order_ttl_ms` 订单过期，过期发生在下一条行情撮合之前。
- 严格行情和涨跌停数据门禁；缺失关键数据时保守失败。

回测绩效的 `executionQuality` 会保留上述约束统计，前端将其作为结果可信度
的一部分，而不是只展示收益率。

## 7. 数据要求与验证

数据订阅声明为 tick + 日线。实时 tick 必须传递 `price_tick`、
`up_stop_price` 和 `down_stop_price`；缺少关键涨跌停数据时策略保守停用。
旧回测数据缺少涨跌停字段时，只有显式设置 `backtest_limit_rate` 才会根据
前收盘价推导上下限，并在行情快照 `source` 中标记 `derived_limits`；该推导
绝不用于 paper/live。

实现测试覆盖：

- 入场意图与仓位上限。
- 缺数据、一字板、已封板、风控禁买、已有持仓等保守阻断。
- pending 防重复、拒单重试和成交状态补丁。
- 退出模板的 T+1、规则顺序与破板状态机。
- 参数默认值、跨字段时段校验和非法配置拒绝。
- 短时委托过期顺序、盘口深度限量和回测约束统计。
- 实际策略、自动回测审批、OrderSizer、统一风控、BacktestBroker、
  BucketLedger、退出计划和 T+1 次日卖出的完整执行链。
- 本地交易日边界、非法时分、实盘账户必填和审批业务失败的前端回归。
- XTQuant tick 到交易域快照的涨跌停字段传递。
