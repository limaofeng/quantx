# QuantX 次日上涨概率选股：完整功能与实现方案

> 文档版本：V2.0
> 更新日期：2026-09-01
> 实现载体：QuantX 单账户 Windows Dev 系统
> 当前状态：首版已落地，训练和模型发布仍由人工控制
> 产品边界：只读研究候选，不生成策略、交易意图、订单或持仓动作

## 1. 合并结论

本方案合并了原产品设计中的“概率化、可解释、可验证”目标，以及 QuantX
现有实现中的数据真源、指标快照、离线研究、Prefect、GraphQL 和 Studio
界面边界。最终采用 QuantX 原生实现，不建设另一套独立选股平台。

保留的产品能力：

- 预测下一交易日开盘到收盘是否上涨；
- 同时训练 Logistic 与 LightGBM，输出经过校准的概率；
- 以严格时间切分和冻结测试集评估，而不是用随机切分；
- 输出候选层级、概率、置信度、模型分歧、校准支持和风险原因；
- 提供模型证据、人工发布和每日推理审计。

删除或延后的范围：

- 多租户、多账户和新的权限体系；
- 实盘下单、模拟下单、仓位分配和策略自动创建；
- 自动训练、自动晋级、自动替换 ACTIVE 模型；
- 未具备 point-in-time 历史的 ST、行业和退市状态推断；
- 将旧研究产物伪装为新版本模型输入。

## 2. 系统边界

### 2.1 首版股票池

只处理普通沪深 A 股：

- 上海：600、601、603、605、688、689；
- 深圳：000、001、002、003、300、301；
- 排除 ETF、指数、北交所、当前 ST、当前停牌和当前退市风险标的；
- 要求至少 252 个有效历史交易日；
- 当前日指标和模型因子完整度不得低于 90%。

股票池过滤在横截面变换之前完成，避免 ETF、ST 或无效标的影响全市场
分位数与标准化结果。

`indicator_snapshots.valid_history_count` 在快照计算时按截至 T 日的有效 OHLC、
正成交量且非停牌记录固化。历史日期推理不得使用会随未来增长的
`Instrument.day_count_from_ipo`。

### 2.2 只读研究候选

候选结果只回答“在当前模型和规则下，哪些股票的次日上涨概率相对较高”。
候选不是交易信号，不进入：

- `StrategyBase.step`；
- `TradeIntent`；
- OrderSizer、风控或 Broker；
- QMT 委托与成交链路。

页面和 GraphQL 必须持续展示这一边界，SHADOW 结果必须带醒目标识。

## 3. 术语与唯一权威契约

日级可展示、可筛选的原始技术量统一称为“指标”；只有机器学习输入的派生、
标准化特征称为“模型因子”。

| 对象 | 唯一名称或版本 |
| --- | --- |
| 日级指标定义 | `IndicatorDefinition` |
| 指标计算版本 | `daily-indicator-v1` |
| 指标计算入口 | `calculate_indicator_frame` |
| 指标研究 | `indicator-study-v1` |
| 模型因子版本 | `next-day-selection-factor-v1` |
| 标签版本 | `next-open-to-close-up-v1` |
| 校准器版本 | `next-day-selection-calibrator-v1` |
| 模型研究 | `next-day-selection-v1` |

旧 `daily-v1`、`factor-study-v1` 及其 GraphQL 名称仅可作为历史审计对象，
不能兼容读取、继续训练或冒充当前版本。代码、数据库、客户端、文档和测试
原子切换到新名称。

## 4. 数据与标签

### 4.1 数据真源

训练复用 QuantX 已审计的历史日线与复权覆盖证明；每日推理只读取当前版本、
全市场 `success` 的认证日级指标快照。部分标的的 `scoped_success`、
失败、失效或旧版本快照不能启动概率推理。同一交易日只认最后一次全市场运行；
若最后一次运行失败或仍在执行，不得回退复用更早的成功快照。

默认训练配置冻结在：

`apps/research/configs/next_day_selection_v1.yaml`

基准窗口为 2021-07-29 至 2026-07-29。配置也允许指定一个已验证的 QMT
archive 或测试专用的确定性 panel，但二者不能同时出现。

### 4.2 精确标签

对每只股票和交易日 T：

```text
return(T+1) = close(T+1) / open(T+1) - 1
label(T) = 1, 当且仅当 return(T+1) > 0
```

标签通过市场交易日历精确连接 T 与 T+1，不能把某只股票的“下一条行情”
当成下一交易日。标签先于 T 日资格筛选构造，避免错误删除用于标签的 T+1
行情。缺少 T+1 开盘或收盘时只将该样本标记为不可训练，不能顺延。

### 4.3 历史股票池证据

ACTIVE 发布要求以下三类 point-in-time 历史全部可用：

- 历史 ST 成员；
- 历史行业归属；
- 历史退市状态。

默认配置明确将三者设为缺失，因此当前研究可以登记为 CANDIDATE 或进入
SHADOW，但不能晋级 ACTIVE。系统不得使用今天的证券状态回填历史。

## 5. 模型因子层

模型因子由日级指标确定性派生，不访问账户、数据库、网络或未来数据。

处理规则：

1. 先按当日合格普通 A 股构造横截面；
2. 连续变量按当日 1%/99% 分位缩尾；
3. 同时生成横截面 z-score 与百分位 rank；
4. MA5/10/20 使用 `MA / current_price - 1` 消除价格尺度；
5. 前 5/20 日均量和前 20 日均额使用 `log1p`；
6. 二值指标只接受 0/1；
7. 每个输入保留显式 missing marker；
8. 训练期中位数、均值、标准差和 0.5%/99.5% OOD 边界写入安全产物；
9. 因子定义、顺序、指标版本和变换共同生成 SHA-256。

推理时必须同时匹配指标版本、因子版本和因子哈希。任何不一致都使该次运行
失败，不进行兼容或降级。

## 6. 训练、校准与选择

### 6.1 唯一训练入口

训练只能人工从仓库根目录启动：

```powershell
uv run --frozen quantx-research train-next-day-selection --config apps/research/configs/next_day_selection_v1.yaml
```

常规 Worker 不自动训练。训练失败保留失败 manifest 和错误证据，不登记模型。

### 6.2 时间切分

最近 60 个完整月份被划分为：

- 最后 12 个月：冻结测试集，只在参数和模型家族确定后使用；
- 之前 48 个月：开发区间；
- 开发区间逐月 walk-forward：最少 30 月训练、随后 6 月校准、再用 1 月验证；
- 每个后续验证月向前扩展训练区间，保持 6 月校准窗口；
- 全部样本和模型拟合使用日期等权权重，避免股票数量多的日期支配结果。

### 6.3 候选模型

Logistic Regression：

- `C ∈ {0.1, 1, 10}`；
- `max_iter = 1000`。

LightGBM：

- `num_leaves ∈ {15, 31}`；
- `reg_lambda ∈ {1, 5}`；
- `learning_rate = 0.03`；
- `n_estimators = 500`；
- `min_child_samples = 100`；
- `subsample = 0.8`；
- `colsample_bytree = 0.8`。

每个家族按 walk-forward 验证 Brier 均值选参数。两个家族再按验证 Brier
比较；若 Logistic 不比 LightGBM 差超过 0.5%，优先 Logistic，以降低复杂度。

### 6.4 概率校准

每个模型家族独立校准：

- 默认使用 Platt；
- 只有校准集正样本不少于 20,000，且 Isotonic 相对改善 Brier 至少 1%，
  才允许选择 Isotonic；
- 校准器本身带版本并写入安全 JSON；
- 每个候选返回其所在校准桶的样本量与实现上涨率。

## 7. 评估与发布门禁

冻结测试集输出：

- Brier Score 与 Brier Skill Score；
- Log Loss、ECE；
- ROC AUC、PR AUC；
- 日期等权 Precision@20、Precision@50；
- Top20/Top50 上涨率、平均收益及相对全股票池提升；
- Top20 上涨率提升的移动区块 Bootstrap 95% 区间；
- 年度 Brier、BSS、ECE 和 Top20 稳定性；
- 10 个校准桶及样本支持。

效果门禁同时要求：

- Brier Skill Score > 0；
- ECE ≤ 3%；
- Top20 上涨率提升的置信区间下界 > 0。

ACTIVE 还要求历史 ST、行业、退市状态完整，以及明确的人工批准。单纯 AUC
较高、某年收益较高或回测样本多都不能替代这些门禁。

## 8. 安全模型产物

模型研究目录位于：

`.runtime/research-runs/next-day-selection-v1/<run-id>/`

核心产物包括：

- `manifest.json`、`resolved-config.yaml`；
- `factor-schema.json`；
- `preprocessing.json`；
- `calibrators.json`；
- `logistic.json`；
- `lightgbm.txt`；
- `model-runtime.json`；
- `metrics.json`、`data-quality.json`；
- `test-predictions.parquet`。

运行时只接受 JSON、LightGBM 原生文本和 Parquet。禁止 pickle、joblib 或
任意 Python 对象反序列化。登记和推理都会验证：

- 路径不能越出运行目录或经过链接；
- 文件类型、数量和字节数有界；
- manifest 身份、状态和必需文件完整；
- 每个文件 SHA-256 与索引一致；
- 特征顺序、版本和哈希与当前运行时一致。

## 9. 模型注册与状态机

状态机：

```text
CANDIDATE → SHADOW → ACTIVE → SUSPENDED
     └──────────────→ RETIRED
SHADOW ─────────────→ SUSPENDED / RETIRED
```

约束：

- 成功研究运行先通过 `registerStockSelectionModel` 登记为 CANDIDATE；
- 最多一个 ACTIVE；
- 最多两个 SHADOW；
- ACTIVE 必须通过全部效果、数据和人工批准门禁；
- 新模型晋级 ACTIVE 时，旧 ACTIVE 在同一事务内转为 SUSPENDED；
- RETIRED 是终态；
- 状态变更使用 `stateVersion` 乐观锁，防止并发覆盖；
- 任何状态转换都不自动触发交易。

## 10. 持久化模型

首版使用五张关系表：

| 表 | 职责 |
| --- | --- |
| `stock_selection_model_versions` | 模型身份、证据、门禁与发布阶段 |
| `stock_prediction_runs` | 每日 ACTIVE/SHADOW 推理运行和失败审计 |
| `stock_predictions` | 全部合格基础股票池的概率、排名和质量证据 |
| `stock_candidate_rule_versions` | 候选阈值和 A/B 数量的版本 |
| `stock_candidates` | 最终只读候选投影 |

预测运行、预测、候选和规则均绑定版本。失败运行不复用旧结果；发布预测和候选
在一个事务内完成。

每次预测运行还固化 `candidate_rule_version`。同一模型同日允许保留多次运行审计，
对外查询先选择当前模型阶段对应的最新尝试，只有该尝试成功才读取其批次；最新
尝试失败或仍在运行时不得回退到更早成功结果。模型从 SHADOW 晋级 ACTIVE 后，
旧 SHADOW 批次也不得伪装为 ACTIVE 结果。

## 11. 每日推理

每日市场数据和指标快照完成后，Prefect 执行概率推理：

1. 找到 ACTIVE 和最多两个 SHADOW；没有运行模型时安全跳过；
2. 要求目标日当前指标版本的最新尝试为全市场成功快照；
3. 冻结合格普通 A 股横截面；
4. 生成因子并原子写入带 SHA-256 的 Parquet 快照；
5. 分别计算 Logistic、LightGBM 和被选家族的校准概率；
6. 计算 OOD、完整度、模型一致性、校准桶支持和综合置信度；
7. 按概率降序、代码升序生成稳定排名；
8. 原子发布预测、A/B 候选与运行终态。

模型阶段切换按模型版本排序锁定整个注册表，再检查“一个 ACTIVE、两个 SHADOW”
约束，避免并发切换出现死锁或数量检查竞态。

综合置信度为以下四项的几何平均：

- 因子完整度；
- OOD fit；
- `1 - |p_logistic - p_lightgbm|`；
- `min(校准桶样本量 / 1000, 1)`。

候选资格同时要求：

- 校准概率 ≥ 0.60；
- 置信度 ≥ 0.60；
- 因子完整度 ≥ 0.90；
- OOD fit ≥ 0.80；
- 无股票池风险标记。

概率、置信度、OOD fit、因子完整度、有效历史长度和 A/B 数量均固化在
`stock_candidate_rule_versions`，推理不得使用未版本化的隐藏阈值。

全股票池先统一排名。A 层只接受总排名 1–20，B 层只接受总排名 21–50。
排名内标的不合格时保留空位，不从第 51 名以后回填。

概率候选查询只读；模型登记和阶段变更属于管理写入，仍不具有交易权限。

### 12.3 `/screening`

页面提供三个明确模式：

- 指标：原有日级指标条件交集；
- 次日概率：A/B 候选、概率阈值、ACTIVE 优先或显式 SHADOW 模型选择、
  代码/名称搜索；
- 盘中：原有实时量能筛选。

概率模式展示：

- 代码、名称、A/B 层级和全池排名；
- 校准概率、置信度；
- Logistic 与 LightGBM 概率；
- 因子完整度、OOD fit；
- 校准桶样本量和历史实现率；
- 入选原因、风险标记、模型版本、T/T+1 日期。

SHADOW 候选顶部必须显示“仅供研究、不得视为交易信号”的醒目横幅。
候选 API 同时提供预测运行、规则版本、因子哈希和因子快照哈希，页面解释列可
直接查看这些追溯标识。

### 12.4 `/research`

研究中心支持 `next-day-selection` 运行，并提供模型注册表：

- 查看模型家族、训练/校准/测试区间；
- 查看冻结测试指标和发布门禁；
- 查看经白名单和有限数校验的数据质量、模型家族、Brier/ECE、Top20/Top50 证据；
- 登记成功研究运行；
- 人工执行 CANDIDATE、SHADOW、ACTIVE、SUSPENDED、RETIRED 转换；
- 明确显示最多一个 ACTIVE、两个 SHADOW 的约束。

## 13. 可审计性与失败语义

每条候选必须可以回溯到：

- 认证指标快照和 cutoff；
- 指标版本、因子版本、因子哈希；
- 模型版本、校准器版本、规则版本；
- 模型阶段；
- 推理运行；
- 原始分数、两个模型概率、校准概率；
- 完整度、OOD、校准桶和原因/风险代码。

以下情况必须失败或跳过，不能静默降级：

- 无 ACTIVE/SHADOW：跳过，不制造候选；
- 快照不完整或版本不一致：拒绝推理；
- 模型产物或哈希不一致：该模型运行失败；
- 模型阶段在推理期间变化：拒绝发布旧阶段结果；
- 任一模型失败：保留独立失败运行，不能复用上日候选；
- 无活动规则：拒绝推理。

## 14. 验收标准

功能验收：

- 指标公共契约中不存在旧 factor GraphQL 名称；
- 训练命令可生成可复现、安全且哈希完整的模型产物；
- T→T+1 标签在停牌、缺行和末日样本上不顺延；
- walk-forward 与最后 12 月冻结测试无交叉；
- 模型家族、校准器和门禁选择符合冻结规则；
- 模型状态数量约束与激活替换在事务内生效；
- ETF、ST、停牌和退市风险标的不参与横截面；
- A/B 候选不回填排名空位；
- SHADOW 页面不被描述为可交易信号；
- 每日推理失败不会发布半成品。

工程验收：

- Alembic 迁移链、表注释和数据库约束通过；
- GraphQL schema、操作策略和客户端类型从 Caddy 公共端点生成；
- Python 单元测试、前端 check/lint/test/build 通过；
- 文档发布契约与运行 schema 一致；
- 完成审核后按 QuantX 规则提交，且不吸收工作区无关改动。

## 15. 后续演进

只有在获得可核验的 point-in-time 历史后，才允许解除 ACTIVE 数据门禁。
后续可按证据逐项增加：

- 历史 ST、行业、退市状态数据集；
- 候选命中后的持续校准监控和漂移报告；
- 人工批准信息的更完整审计页面；
- 新模型家族，但必须沿用同一标签、时间切分、冻结测试和安全产物规范。

任何后续版本都不得把概率候选直接接入策略或交易；若产品边界发生变化，
必须另行设计交易域契约、风险门禁和用户授权。
