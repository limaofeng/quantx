**文档目标:** 定义面向 A 股单标的动态天平双仓策略的 GA 进化系统。进化引擎是纯计算黑盒，不理解具体策略公式，不突破 A 股交易规则，只通过抽象接口驱动种群生命周期。具体染色体字段、边界、适应度细节由策略适配器提供。

---

## 0. 核心定位

进化引擎是一个**纯计算线程**：接收 A 股策略提供的基因空间、历史数据坩埚和评估函数，对种群执行多代进化，交付最优候选参数包。

当前主线策略：`ashare_dynamic_balance_dual_bucket`。

引擎不关心：

- 个股趋势信号如何计算。
- 动态基准如何组合 EMA、ATR 和成交量分布。
- `core / swing / locked_core` 的内部语义。
- T+1 库存置换的具体记账流程。
- 环境层、风控层、仓位调节层内部规则。

引擎只知道：基因是可采样、可变异、可交叉、可评分、可编码的抽象载体。

输入：

- 策略提供的基因空间、边界和结构约束。
- A 股历史数据集：个股行情、指数、行业、概念、市场宽度、交易日历、停牌、涨跌停、公司行为。
- 出生点参数：初始资金、月度注资、单票硬仓位上限、最低现金缓冲、手续费、印花税、滑点、最大回撤等。
- 进化配置：种群大小、代数、变异概率、变异幅度、早停参数等。

输出：

- `challenger` 参数包 JSON，写入数据库。
- 回测指标、各窗口分数、风险原因、成交约束统计与审计摘要。
- 等待人工审核后 Promote 为 `champion`。

## 1. 探索窗口定义

### 1.1 A 股数据坩埚

Epoch 启动时，引擎一次性从数据库拉取本次评估所需的历史数据，构造只读 `EvaluablePlan`。

A 股回测不是只需要单只股票 K 线，还必须包含策略在同一时点可见的外部环境：

- 标的个股日线、分钟线或 tick。
- 大盘指数：上证指数、沪深300、中证500、中证1000、创业板指、全A指数等。
- 标的绑定的主行业指数。
- 可选概念指数。
- 全市场成交额、上涨家数、下跌家数、涨停家数、跌停家数。
- 交易日历、交易时段、停牌信息、涨跌停价、ST / 退市风险标签。
- 公司行为与复权因子。

成交撮合必须使用未复权真实价格、真实涨跌停和停牌约束；指标计算可使用时点可得的复权序列，但不得引用评估时点之后的复权因子或公司行为。

### 1.2 多窗口坩埚

A 股以交易日为基本计量单位。窗口对齐最新一个完整交易日，短窗口优先评估，用于级联短路。

| 窗口标识 | 评分区间 | 近似含义 | 适应度权重 |
|---|---:|---|---:|
| `6m` | 最近 120 个交易日 | 半年 | 0.10 |
| `2y` | 最近 480 个交易日 | 两年 | 0.20 |
| `5y` | 最近 1200 个交易日 | 五年 | 0.30 |
| `full` | 自上市或最早可得交易日至最新交易日 | 全量历史 | 0.40 |

每个窗口在评分区间之前预留 warmup 前缀，默认最多 750 个交易日，用于 EMA、ATR、价格分位、成交量分布等指标预热。warmup 不计入评分。

如果标的上市时间不足窗口长度，则使用可得历史构造窗口，并在结果中标注 `data_span_short`。若有效交易日少于策略最低窗口要求，则该标的不允许进化或只允许测试模式。

### 1.3 严禁未来数据泄露

每个窗口的评估区间从 `EvalStartMs` 开始，warmup 数据必须严格早于 `EvalStartMs`。

禁止：

- 使用未来复权因子。
- 使用未来停牌/复牌信息。
- 使用未来涨跌停价。
- 使用未来行业成分变化结果倒推当前行业状态。
- 用日线 high/low 推断盘中先后顺序，除非有分钟/tick 数据证明。
- 在当前 bar 未完成时使用其收盘价做决策。

### 1.4 基因空间窗口

策略通过以下语义向引擎暴露基因空间，引擎不直接读取字段名：

- `Sample(rng)`：从合法空间随机生成基因。
- `Clamp(gene)`：将越界基因修复到合法范围，并修复结构约束。
- `Validate(gene)`：验证基因是否合法。
- `Fingerprint(gene)`：对量化后的基因生成稳定指纹。

可进化参数只允许是软策略参数，例如：

- 动态天平信号权重。
- `balance_beta`、`inventory_gamma`。
- 中性仓位、core 默认占比、网格 ATR 倍数。
- 低位评分阈值、高位出货阈值、下跌保护阈值。
- 环境评分权重、profile 切换阈值、beta/gamma multiplier。

不可进化参数：

- A 股交易规则。
- 100 股整数倍。
- T+1。
- 涨跌停与停牌约束。
- miniQMT 成交真源规则。
- 单票硬仓位上限。
- 最低现金缓冲硬下限。
- 是否允许 `locked_core` 做库存置换。
- 最大回撤熔断硬阈值。

### 1.5 出生点冻结窗口（Epoch 级）

`AshareSpawnPoint` 在 Epoch 启动时确定，全种群共享，不参与代内交叉变异，不进入基因组指纹。

出生点包括：

```text
AshareSpawnPoint
├── CapitalPolicy
│   ├── initial_cash_cny
│   ├── monthly_inject_cny
│   ├── min_order_amount_cny
│   └── cash_buffer_floor_pct
├── RiskBounds
│   ├── max_position_pct
│   ├── max_daily_add_pct
│   ├── max_single_order_pct
│   ├── max_drawdown_pct
│   └── kill_switch_rules
├── TradingRules
│   ├── lot_size = 100
│   ├── allow_odd_lot_liquidation
│   ├── price_tick
│   └── session_policy
└── CostModel
    ├── commission_pct
    ├── min_commission_cny
    ├── stamp_tax_pct_sell
    ├── transfer_fee_pct
    └── slippage_model
```

`spawn_mode`：

- `inherit`：继承当前 champion 或系统默认出生点。
- `random_once`：排队时抽样一次并冻结。
- `manual`：请求体填写出生点 JSON。

## 2. 进化生命周期动作

### 2.1 种群初始化

默认参数：

| 参数 | 默认值 |
|---|---:|
| `Population` | 300 |
| `MaxGenerations` | 25 |
| `Elitism` | 8 |
| `TournamentSize` | 3 |
| `MutationProbability` | 0.15 |
| `MutationScale` | 1.0 |

当数据库中存在精英基因时：

- 索引 0：当前种子 champion 原样。
- 约 10%：从历史精英中原样拷贝。
- 约 40%：在精英基础上施加强化高斯变异，固定 `prob=0.15`、`scale=1.5`。
- 约 50%：完全随机生成。

当数据库无精英时：

- 索引 0：产品默认种子染色体。
- 其余个体：完全随机生成。

初始化后必须调用策略的 `Clamp` 与 `Validate`，无效个体进入修复或替换流程。

### 2.2 并发适应度评估

评估采用固定大小 worker pool：

```text
Workers = min(NumCPU, PopulationSize)
```

每个 worker 独占一份回测上下文与 broker 状态，不共享可变组合状态。

A 股回测上下文必须包含：现金、持仓、可卖量、今日买入、冻结资金、冻结股份、bucket 归因、委托状态、成交状态、交易日历、涨跌停、停牌和费用模型。

### 2.3 选择（Tournament）

每次从种群中随机抽取 `TournamentSize=3` 个不同个体，取适应度最高者为父代。

fatal 个体分数极低，会自然被淘汰，无需显式过滤。

### 2.4 交叉（Uniform Crossover）

对每个基因维度以 0.5 概率从两个父代中选择来源。交叉后调用策略的 `Clamp` 修复结构约束。

引擎不理解“趋势权重”“低位阈值”“网格倍数”等字段含义。

### 2.5 变异（加性高斯）

每个基因维度以独立 Bernoulli 概率 `MutationProbability` 决定是否变异，变异量：

```text
NormFloat64() × GeneStep × MutationScale
```

变异后调用 `Clamp` 与 `Validate`。

### 2.6 精英保留

每代保留适应度 Top `Elitism` 个体，直接进入下一代，不经过交叉与变异。

### 2.7 收敛检测与变异斜坡

连续 `EarlyStopPatience=5` 代内最佳适应度改善低于 `EarlyStopMinDelta=0.001` 时触发变异斜坡：

```text
MutationProbability *= 1.25
MutationScale       *= 1.25
```

上限：

```text
MutationProbabilityMax = 0.55
MutationScaleMax       = 3.0
```

当二者均触及上限后仍无改善，才 Early Stop。

### 2.8 Genome 指纹缓存

策略提供 Fingerprint 语义，对基因向量按精度 `1e-6` 量化后哈希。Epoch 内重复个体命中缓存时复用评估结果，跳过重复回测。

缓存 key 不包含出生点，因为同一 Epoch 内出生点冻结；不同 Epoch 不复用缓存。

### 2.9 收敛交付

进化结束后，将最优基因和冻结出生点编码为 `ParamPack` JSON，写入数据库为 `challenger`。

进化任务不自动 Promote。必须人工查看回测报告、风险摘要、成交约束统计和各窗口表现后晋升。

## 3. A 股适应度黑盒

### 3.1 基准：Ghost 定投

`SimulateGhostAshareDCA` 作为被动对照组：

1. 在首个可交易日，用初始资金尽可能买入标的，按 100 股整数倍下单，剩余现金保留。
2. 每个自然月第一个可交易日注入 `monthly_inject_cny`。
3. 注资资金在可成交时尽可能买入标的。
4. 若停牌或涨停不可买，则保留现金到下一个可交易日。
5. 不主动卖出。
6. 计算同一费用模型下的 NAV、ROI 和最大回撤。

Ghost DCA 不是最优策略，只是被动长期持有加定投基准。策略个体必须相对它产生正 Alpha 才有意义。

### 3.2 ROI 与 NAV

策略 NAV：

```text
NAV = cash + frozen_cash + market_value(position_total) - fees_accrued
```

ROI 使用 Modified Dietz 思路，剔除月度注资导致的权益跳变：

```text
ROI = (EndingEquity - BeginningEquity - ΣCashFlow)
      / (BeginningEquity + Σ(CashFlow_i × Weight_i))
```

最大回撤基于每日收盘后的 NAV 曲线计算。若有分钟级回测，可同时记录盘中最大回撤，但总评分默认使用日终 NAV，避免不同数据粒度不可比。

### 3.3 多窗口分数

每个窗口计算：

```text
AlphaDCA = ROI_strategy - ROI_GhostDCA

ExcessDD = max(0, MaxDD_strategy - MaxDD_GhostDCA)

SliceScore = AlphaDCA
           - 1.5 × ExcessDD
           - TurnoverPenalty
           - ExecutionPenalty
           - RuleViolationPenalty
```

默认惩罚项：

- `TurnoverPenalty`：过度换手惩罚，防止网格在 A 股成本下无效交易。
- `ExecutionPenalty`：大量意图因涨跌停、停牌、T+1、流动性不足无法成交时惩罚。
- `RuleViolationPenalty`：任何试图突破 A 股硬规则的行为为高额惩罚，严重时 fatal。

加权汇总：

```text
ScoreTotal = 0.40 × Score_full
           + 0.30 × Score_5y
           + 0.20 × Score_2y
           + 0.10 × Score_6m
```

### 3.4 Fatal 硬否决

以下情况立即返回 fatal 分数 `-99999`：

1. `MaxDD_strategy >= 0.60`，默认 A 股单标的灾难回撤阈值为 60%。该阈值可由出生点风险边界进一步收紧，但 GA 不得放宽。
2. 账户权益低于最小安全权益阈值。
3. 出现违反 A 股交易规则的成交假设，例如停牌成交、涨停默认买入成交、跌停默认卖出成交、T+1 不可卖却直接卖出。
4. 策略或回测 broker 把信号直接标记为成交。
5. bucket 归因总量与真实持仓模拟总量不可对账。
6. `locked_core` 被方向性卖出，且实例未显式允许该行为。
7. 熔断规则触发后仍继续新增买入。

### 3.5 级联短路

适应度评估顺序：

```text
6m → 2y → 5y → full
```

一旦某个窗口 fatal，立即返回 fatal，跳过后续更长窗口。

这样可以快速淘汰明显不适应近期 A 股交易约束或极端风险的个体。

## 4. A 股回测 broker 约束

GA 评估必须使用保守回测 broker，不得使用理想成交。

### 4.1 交易时段

v1 默认只允许连续竞价：

- 09:30–11:30
- 13:00–15:00

集合竞价是否参与由出生点或实例配置控制，默认关闭。

非交易时段意图只能排队或拒绝，不得成交。

### 4.2 数量规则

- 买入必须为 100 股整数倍。
- 普通卖出以 100 股整数倍为主。
- 清仓允许零股卖出。
- 不满足最小成交金额时拒绝。
- 超出最大申报数量时拆单或限额。

### 4.3 价格与状态规则

必须校验：

- price tick。
- 涨停价、跌停价。
- 停牌状态。
- 是否一字涨停或一字跌停。
- 是否存在可成交价格与可成交量。

默认保守规则：

- 涨停买入默认不成交，除非分钟/tick 或盘口数据证明打开。
- 跌停卖出默认不成交，除非分钟/tick 或盘口数据证明打开。
- 停牌不成交。
- 日线 high/low 触达不代表一定成交；没有分钟/tick 时使用保守撮合。

### 4.4 T+1 与库存置换

回测 broker 必须维护：

- `total_volume`
- `available_volume`
- `today_buy_volume`
- `frozen_volume`
- bucket 级可卖量

当 swing 当日买入后又触发卖出：

1. 先使用 `swing_available`。
2. 不足时可使用 `core_available` 做库存置换。
3. 仅当 `allow_locked_core_substitution = true` 时，才可使用 `locked_core_available` 做库存置换。
4. 不足部分 `DELAY` 或 `REJECT`。

置换必须按成交数量确认；拒单、撤单和部分成交必须可回滚。

### 4.5 费用模型

回测必须计入：

- 买卖佣金。
- 最低佣金。
- 卖出印花税。
- 过户费。
- 滑点。
- 部分成交导致的剩余挂单管理成本。

网格收益低于交易成本与安全边际时，策略意图应被过滤或在评分中受到惩罚。

## 5. 性能优化机制

已落地或应保留：

**5.1 级联短路**

短窗口 fatal 立即退出，减少长窗口无效计算。

**5.2 并发评估**

Genome 粒度 worker pool，worker 数上限为 CPU 数量。

**5.3 指纹缓存**

同一 Epoch 内重复基因复用评估结果。

**5.4 DCA 基线预计算**

每个窗口的 Ghost A-share DCA 在 Epoch 启动时预计算一次，代内复用。

规划但未实现：

**5.5 日线快筛 + 分钟复核**

先用日线 broker 快速淘汰明显差的基因，仅对 Top 个体进行分钟级复核。该机制只能作为性能优化，最终 challenger 必须通过完整目标粒度回测。

**5.6 前缀统计缓存**

对 EMA、ATR、价格分位、成交量分布、市场宽度等统计构建增量缓存，减少重复计算。

**5.7 Nested Replay 谨慎使用**

嵌套重放与级联短路存在冲突。A 股短窗口 fatal 率较高时，强制先跑 full 可能显著变慢。只有当 fatal 率很低且全量 replay 可复用大量状态时才考虑。

## 6. Epoch 验证与压力测试

Epoch 进化完成后，候选 champion 应执行额外验证。当前可按实现能力分阶段落地。

### 6.1 全样本复核

对最优候选在全样本目标粒度上重跑一次，确保 worker 缓存、warmup 和适配器不会影响结果。

### 6.2 A 股极端场景压力测试

必须覆盖：

- 连续涨停导致买入意图无法成交。
- 连续跌停导致卖出意图无法成交。
- 长期停牌。
- 高位放量滞涨后快速下跌。
- 低位横盘后缓慢修复。
- 当日买入后触发卖出，库存置换可用与不可用两种情况。
- 行业破位但个股技术低位。
- 大盘 `PANIC` 环境。

### 6.3 蒙特卡洛风险评估（规划）

对成交收益序列、隔夜跳空和不可成交事件进行重采样，输出：

- 破产概率或权益低于阈值概率。
- 终局权益第 5、50、95 分位。
- 最大回撤分位。
- 连续不可卖场景下的现金缓冲压力。

### 6.4 WFO 推进式滚动测试（规划）

按时间轴做 Walk-Forward Optimization，防止过拟合。该机制不应阻塞当前 v1，但 Promote 前应尽量查看滚动区间表现。

## 7. 结果交付与基因角色

### 7.1 基因角色三态

| 角色 | 含义 |
|---|---|
| `challenger` | 进化产出，等待人工审批 |
| `champion` | 当前活跃冠军，驱动实例创建或参数更新 |
| `retired` | 历史冠军，仅供回溯与审计 |

### 7.2 ParamPack 内容

A 股 ParamPack 至少包含：

```json
{
  "strategy_id": "ashare_dynamic_balance_dual_bucket",
  "version": "v1",
  "spawn_point": { "...": "..." },
  "ashare_dynamic_balance_config": { "...chromosome fields...": "..." },
  "fitness_summary": {
    "score_total": 0.0,
    "max_drawdown": 0.0,
    "alpha_vs_ghost_dca": 0.0,
    "window_scores": []
  },
  "execution_summary": {
    "turnover": 0.0,
    "rejected_intents": 0,
    "t1_substitutions": 0,
    "limit_blocked": 0,
    "suspension_blocked": 0
  }
}
```

### 7.3 人工 Promote 流程

操作员在前端查看候选参数：

- 综合评分。
- 各窗口表现。
- 相对 Ghost DCA Alpha。
- 最大回撤。
- 交易成本与换手。
- 因 T+1、涨跌停、停牌导致的拒单/延迟统计。
- 压力测试摘要。

晋升操作在数据库事务中执行：

1. 当前 `champion` 改为 `retired`。
2. 选定 `challenger` 改为 `champion`。
3. 记录激活时间与操作人。
4. 删除 Redis `champion:{strategyID}` 缓存。
5. 下一次实例 tick 自动加载新 champion。

Promote 不应自动修改正在运行实例的硬风险边界；硬边界由实例配置和出生点风险策略控制。

## 8. HTTP 触发契约

进化任务只在 `app_role: lab` 或 `dev` 下可用。

### 8.1 创建进化任务

`POST /api/v1/evolution/tasks`

请求参数：

| 字段 | 说明 |
|---|---|
| `strategy_id` | 默认 `ashare_dynamic_balance_dual_bucket` |
| `instrument_code` | 标的代码，例如 `600000.SH` |
| `sector_code` | 绑定行业指数，可选但推荐 |
| `concept_codes` | 概念指数列表，可选 |
| `pop_size` | 默认 300，范围 [10, 500] |
| `max_generations` | 默认 25，范围 [5, 50] |
| `spawn_mode` | `inherit` / `random_once` / `manual` |
| `spawn_point` | `manual` 时必填 |
| `data_mode` | `daily` / `minute` / `daily_then_minute_verify` |
| `test_mode` | 快速测试模式，Pop=10, Gen=3 |
| `warmup_trading_days` | 默认 750 |

创建任务时必须校验：

- 标的历史数据是否足够。
- 交易日历是否完整。
- 停牌与涨跌停数据是否可用。
- 行业数据缺失时是否允许降级。
- 出生点硬风险边界是否合法。

### 8.2 查询任务状态与结果

`GET /api/v1/evolution/tasks`

返回：

- 当前任务是否运行。
- 当前代数、最大代数、最佳分数、当前变异参数。
- 历次 `challenger` 列表。
- 每个候选的 `ScoreTotal`、`MaxDrawdown`、各窗口分数。
- 成交约束统计：拒单、延迟、涨跌停阻塞、停牌阻塞、T+1 置换次数。

### 8.3 Promote

`POST /api/v1/evolution/tasks/:taskID/promote`

只能 Promote 该任务产出的 `challenger` 或指定 `gene_id`。Promote 必须记录审计日志。

## 9. EvolvableStrategy 抽象接口

进化引擎通过接口与具体策略完全解耦。

### 9.1 九动词契约

| 动词 | 职责 |
|---|---|
| `StrategyID()` | 返回策略唯一标识符 |
| `Sample(rng)` | 从合法基因空间随机采样 |
| `Mutate(c, prob, scale, rng)` | 对基因施加高斯变异 |
| `Crossover(p1, p2, rng)` | 两个父代均匀交叉 |
| `Fingerprint(c)` | 返回基因稳定哈希，精度 1e-6 |
| `Evaluate(ctx, c, plan)` | 在给定 A 股坩埚计划上评估基因 |
| `DecodeElite(json)` | 从 DB ParamPack 解码精英基因；失败返回默认种子 |
| `EncodeResult(c, spawn)` | 将基因与出生点编码为 ParamPack JSON |
| `Verify(ctx, c, spawn, plan)` | 对候选做全量复核、压力测试或 Monte Carlo |

`Gene = any`：引擎持有不透明载体，不读取内部字段。

### 9.2 EvaluablePlan 只读上下文

`EvaluablePlan` 在 Epoch 启动时构建，在整个世代内不可变。

```text
EvaluablePlan
├── StrategyID
├── InstrumentCode
├── SectorCode / ConceptCodes
├── Spawn *AshareSpawnPoint
├── TradingCalendar
├── TradingRules
├── CostModel
├── Windows []AshareCrucibleWindow
│   ├── SignalBarsAdjusted
│   ├── ExecutionBarsRaw
│   ├── IndexBars
│   ├── SectorBars
│   ├── ConceptBars
│   ├── BreadthSeries
│   ├── LimitStatusSeries
│   ├── SuspensionSeries
│   └── EvalStartMs
├── DCABaselines []AshareDCABaseline
└── AggregateCache
```

DCA 基线在 Epoch 启动时一次性计算，代内各染色体评估直接读取。

### 9.3 策略适配器职责

`AshareDynamicBalanceEvolvable` 位于 `internal/saas/ga/ashare_dynamic_balance_evolvable.go`，避免策略包导入 GA 与回测造成循环依赖。

职责：

- 定义染色体字段、边界、步长和结构约束。
- 实现 Sample / Mutate / Crossover / Clamp / Fingerprint。
- 调用回测适配器执行单窗口回测。
- 计算窗口分数、fatal、成交约束统计。
- 编码 ParamPack。

引擎本体 `engine.go` 不允许出现任何 A 股策略字段名。

## 10. GA 可优化与不可优化边界

### 10.1 可优化软参数

示例：

- 趋势、偏离、成交量、风险、阶段信号权重。
- `balance_beta`、`inventory_gamma`。
- `neutral_position_pct`。
- `core_base_share`。
- `grid_atr_multiplier`。
- 低位加仓阈值。
- 高位出货阈值。
- 下跌保护阈值。
- 环境评分权重。
- profile 切换阈值。
- beta/gamma multiplier。
- grid step multiplier。

### 10.2 不可优化硬约束

- T+1。
- 100 股整数倍。
- 停牌不成交。
- 涨停买入 / 跌停卖出的保守撮合规则。
- 手续费和印花税真实规则下限。
- 单票硬仓位上限。
- 最低现金缓冲硬下限。
- 最大回撤熔断硬阈值。
- miniQMT 成交真源。
- 用户封存仓方向性卖出禁区。
- 数据无未来泄露原则。

GA 找的是“在硬规则内更好的软参数”，不是找绕过真实交易规则的方法。

## 11. 验收测试计划

### 11.1 引擎行为测试

- 种群初始化时 index 0 为当前种子 champion。
- 有精英时 10% 原样、40% 强化变异、50% 随机的比例近似正确。
- 精英保留后 Top N 个体进入下一代。
- 变异斜坡在连续无改善后按 1.25 放大。
- fatal 个体在锦标赛中被选中的比例极低。
- 指纹缓存命中时不重复回测。

### 11.2 A 股规则测试

- 停牌不成交。
- 非交易时段不成交。
- 涨停买入默认不成交。
- 跌停卖出默认不成交。
- 买入数量必须为 100 股整数倍。
- 卖出清仓允许零股。
- T+1 当日买入不可卖。
- 有 core 老仓时可做 swing 库存置换。
- `allow_locked_core_substitution=false` 时不得使用 locked_core。
- 部分成交只更新部分 bucket 归因。
- 拒单或撤单必须回滚冻结和置换计划。

### 11.3 适应度测试

- 相同参数回测两次，输出完全一致。
- 策略 ROI 与 Ghost DCA ROI 计算符合 Modified Dietz。
- MaxDD 超过 fatal 阈值立即短路。
- 违反交易规则的个体返回 fatal。
- 短窗口 fatal 时不执行长窗口回测。
- 成交成本提高时，高换手策略分数下降。

### 11.4 数据泄露测试

- 评估区间不得读取未来 bar。
- warmup 数据不计入评分。
- 复权因子不得引用评估时点之后事件。
- 行业/概念数据缺失只能降级，不得生成激进环境评分。

## 12. 设计结论

A 股进化引擎的核心不是追求理想收益最大化，而是在真实 A 股约束下寻找稳健参数。

必须同时满足：

1. 回测与实盘同构。
2. A 股规则不可突破。
3. miniQMT 成交真源不可伪造。
4. 环境、风控、仓位调节、策略、执行分层清晰。
5. GA 只优化软参数，不优化硬规则。
6. Promote 前必须查看多窗口表现、风险指标、成交约束统计和压力测试摘要。

## 附录 A. A 股回测 broker 与交易域契约

GA 进化不能直接把策略信号视为成交。每个染色体评估必须经过以下统一链路：

```text
历史行情 / 交易日历 / 证券状态 / 公司行为
    -> MarketContextSnapshot
    -> RiskContextCaps
    -> PositionAdjustmentProfile
    -> Strategy.Step()
    -> TradeIntent
    -> OrderSizer
    -> OrderRiskDecision
    -> BacktestBroker
    -> BrokerExecutionReport
    -> RuntimeStateManager / BucketLedger
    -> Fitness Metrics
```

回测 broker 必须遵守：

- 使用未复权价格撮合。
- 停牌不成交。
- 涨停买入默认不成交，除非数据证明打开。
- 跌停卖出默认不成交，除非数据证明打开。
- T+1 可卖量必须模拟。
- 100 股整数倍、零股清仓、费用、印花税、滑点和成交量参与率必须模拟。
- 部分成交只更新部分 bucket。
- 库存置换必须通过 `SubstitutionPlan` 提交或回滚。
